### J5 Lazy loading: spike result and mechanism
**Spike (D2 of wave 6): passed.** `pnpm run build` emitted `dist/data-table/lazy/{range,clipboard,row-drag,filter-panels,filter-builder}.js` (the five new entries) and `dist/chunks/data-table.js` contains `import("../data-table/lazy/range.js")` (and the other four): rollup rewrites the relative specifier to the entry file from whatever chunk the call lands in, and the file exists. The icons' `import('../icon/define.js')` (`data-table-icons.ts`) is emitted the same way. The published package resolves it: a relative import inside a package is not subject to its `exports` map, so the lazy files need no `exports` line. `scripts/size.mjs` counts what it should: its static-import regex does not match `import("...")`, so the lazy entries are NOT in `data-table/define.js` / `index.js` and each is measured and budgeted as its own entry (a stub is 20 to 140 B gzip); a shared chunk that a lazy entry and `define` both import counts in both, which is the conservative reading. Chosen mechanism for BOTH waves: **a build entry per lazy module, reached by a plain relative `import()` written in the code that needs it, behind `data-table-lazy.ts`.** Wave 5 lazy: the three panels (`lazy/filter-panels`), the builder (`lazy/filter-builder`), `ge-date-picker` (its own define entry). Wave 6 lazy: range and fill (`lazy/range`), paste (`lazy/clipboard`), row drag (`lazy/row-drag`); copy and flash stay eager. Wired already, so the mechanism is exercised end to end: `RangeSession`, `ClipboardController`, `RowDragController` call `lazyPart(...).sync(flag)` from `hostUpdate`, and `FilterUiController.prefetch()` calls `lazyElement(...).load()`; the loaded parts are empty classes. No addon fallback is needed.

### J9 Contract changes from review round 1 (they amend J1 to J8)
- **Retained row and drag CSS:** the drag rule is `[data-draggable]:not([data-retained])`, so a retained focused row stays `position: absolute` whatever the order of the region files.
- **Rows are draggable only when the drag part handles drags:** new `RowDragService.active()` (the step 0 shell answers false; wave 6 C answers true once its part is attached). `stateView` emits `draggable`, `data-draggable`, `data-dragging` and the drop-edge child only then.
- **Range value lives in the shell:** `RangeSession` holds the range between the part's lives. `setRange` before the part is loaded (or between attach and load) and a range kept across a detach and attach are handed to the next `RangePart` through `part.setRange(...)` before it attaches, and read back with `part.getRange()` before it is disposed. The part contract for wave 6 A: keep `getRange()` and `setRange()`. The element's `earlyRange` stays: it covers only a value set before the controllers exist.
- **One implementation per pair:** the shell's `cellRange()` and `isCellSelected()` are derived from `rangeService.range()` and `isInRange()` (`isCellSelected` = in range, else the focused cell). Wave 6 A implements `rangeService`. `RangeService.edgeOf(rowIndex, columnKey)` replaces the edge computation in `stateView`; the pure `rangeEdges(range, rowIndex, col)` is in `data-table-range.ts` for it to call.
- **Lazy failures are latched:** `lazyPart.sync(true)` after a failed load does nothing (no re-import, no second log) until the flag turns off, or `dispose()` (the next attach). The dead `loading` state is gone.
- **Diagnostics snapshot:** `sortState` and `multiSortState` enter it only with `enable-row-drag` and `local-reorder` on (the one check that reads them), so a sort no longer re-runs the config check and the O(rows) id scan.
- **`stateView` allocates nothing in range mode without a range:** shared frozen objects for the out-of-range cells (`OUT_OF_RANGE_FLAGS`, `OUT_OF_RANGE_EDITABLE_FLAGS`); the row id and the disabled flag are computed once per row, not per cell.
- Removed unused exports `CellSessionFactory` and `KeyOwner`; the five `copy*ToClipboard` element methods share one private helper.

**Round 2 (amends the above):**
- **The part's range is authoritative while a part is attached** (`part ? part.getRange() : held`, so a part that cleared its range stays cleared, also at detach). The shell reads it back at EVERY update and at detach, so no dispose can leave a stale `held`.
- **Turning the range flags off clears the range** (wave 6 A.2: "turned off clears the range and removes listeners"); turning them on again starts empty. A DOM move (detach and attach with the flags still on) keeps it.
- **A row that shows a drop edge carries `data-drop-target`** and the drag CSS positions `[data-draggable]` and `[data-drop-target]` rows (not retained ones), so a disabled target or a loading table still lays its absolute edge out against its own row.
- `rowState` compares the dragged id as `String(rowId)` (`getRowId` may answer numbers).
- **`cellRange` on the element:** reclaimed in the constructor like the model keys (a value set before the upgrade goes through the setter); read while detached from the snapshot the element takes at disconnect (the services are gone then) and given back at the next connect.
- **Selection Space:** no editor guard in the selection controller (see J3); the priority table owns it. Test: an editor "open" in row 1 does not stop Space on row 3.

**Round 8 (amends the above; the press contract is final for wave 6's range and fill drags):**
- **One `Press` per pointer id** (a `Map`, multi-touch safe), created at pointerdown with `anchor` = the roving cell read BEFORE the offer (a claimant that moves the focus in its own `onPointerDown` does not change its press's anchor) and `claimedBy`. **Round 9 (amends the above):**
- **A press ends even when something stops propagation:** the controller's press ends are heard in the CAPTURE phase. - **parity/run.mjs:** `data-edit` runs before the animation wait (after the table's own `data-props`), so a transition the open editor starts is awaited.

**Round 10 (amends the above; round 9's "empty data ends the range" is reverted):**
- **A press is closed by its POINTER ID.** Presses are recorded in the CAPTURE phase on the table's root (own events only; an inner `stopPropagation` cannot hide a press, so a touch tap on a cell whose content stops pointerdown still focuses it), and ended by the document's capture `pointerup` / `pointercancel` wherever the pointer is released: a pointerup on THIS table's own cells (not outside, not over a nested table in a detail row) ends it as an up (claimant: `onPointerUp`; unclaimed: offered, touch tap focuses), any other end is `onPointerCancel` for its claimant. The root's own up / cancel listeners are gone. A release with no recorded press (the pointer went down outside the table) still does nothing (round 8): with presses recorded in capture, "no press" can only mean that.

ACCEPTED EDGE: a range kept across a genuinely empty phase is trimmed onto the first rows of a later load.

When false the renderer uses the pre-step-0 cell and row templates and never calls `cellState` / `rowState` (node test counts the calls). Consequence for the waves: the rows switch template (the DOM is rebuilt once) when `stateActive` flips, e.g. when the range or drag part becomes active; an editor needs an `editable` column, so it never flips the flag by itself.
- **Kit:** `touchLongPressDrag` is `touchDrag(..., { holdBeforeMs })`. **Controllers:** `services` is a readonly field set once and `service(key)` reads it once per controller.

## 0. What the reading changed (read first)

1. **Angular has no built-in per-type column filter UI.** The header shows a filter button only when `col.enableFiltering && col.filterComponent` (html 633-705); it opens a popover hosting the CONSUMER's component. `DataTableDateFilterComponent`, `DataTableDateRangeFilterComponent` and `DataTableMultiselectFilterComponent` (sub/) are ready-made components a consumer passes as `filterComponent` together with `filterFn: dateFilterFn / dateRangeFilterFn / multiselectFilterFn`. So the wave covers: text (floating input and the default `textIncludes`), date, date-range, multiselect, and any custom component; number and boolean get nothing built-in (D1).
2. **The table never tells a filter panel what the filter currently is.** `getFilterInputs` (cmp 3846-3857) returns only the consumer's `filterComponentInputs`; the panels' `selected` input is fed by nobody unless the consumer wires it. ## 3. Design

### 3.1 Packages' internals
**FilterUiController** (`data-table-filter-controller.ts`, id `filter-ui`, provides `filters`). Owns no model state (the model owns `columnFilters` / `advancedFilter`); it draws the toolbar trigger and badge, holds the popover open state of the builder, subscribes (internal origin only) to `columnFilters` and `advancedFilter` for the debounced announcement (cancelled on detach; reads `query.filteredCount()` when the timer fires: the wave 4 lesson), and prefetches the lazy panels on `pointerenter` / `focusin` of a trigger (and again on open). It never imports another controller.
**`data-table-grid-filters.ts`** draws the header trigger and the floating row from `GridView.filters`; the trigger markup is a plain `button` so `ge-popover-trigger` can wrap it; every control keeps `tabindex` natural (header controls are tab stops, as the sort buttons are).
**EditSession** (`data-table-edit-session.ts`, package B) owns `editing`, `error`, `draft`, `editingRowId`, a double-tap detector and its own key and pointer handlers; `hostUpdate` runs `reconcileEditor(state, rows, getId)` from `data-table-edit.ts` (pure, node-tested: follows the row, drops it silently, keeps an empty list as is, moves the error with the editor) and publishes `retain('edit', ...)`. **`data-table-grid-edit.ts`** draws the editor for `GridView.edit.cell` and sets `aria-invalid` / `aria-describedby`; the error id is `ge-dt-<uid>-edit-error`.
**Pure modules** (node): `data-table-filters.ts` (the three `*FilterFn`, `isActive`, `hasFloating`, builder tree operations, multiselect toggle / select-all / clear with Angular's semantics) and `data-table-edit.ts` (`reconcileEditor`, `decideCommit` (unchanged -> cancel, repeated rejection -> stay, else write), `tabTarget`, `coerceDraft(kind, raw, options)`, `createDoubleTap`, `historyKey(event)`).

### 3.2 Locale keys (step 0, en only; every key has an interpolation noted)
`filterColumnActive` ("Filter {column}, filter applied"), `filtersClearedAnnouncement`, `filteredRowsAnnouncement` ("{count} rows match the filters"), `filteredRowOneAnnouncement`, `invalidValue` ("Invalid value"), `editCell` ("Edit {column}", the editors' accessible name), `undoAnnouncement`, `redoAnnouncement`, `historyStaleAnnouncement` ("{count} changes skipped: their rows or columns no longer exist"); optional keys on `FilterBuilderLabels` with English fallbacks: `columnLabel`, `operatorLabel`, `valueLabel`, `groupLabel` (accessible names the Angular builder lacks, B6). The panels take Today / Clear / presets from `CALENDAR_LOCALES`.

### 3.3 Details that decide behaviour
- **Selection of the active popover content**: `ge-popover-content` is not rendered while closed, so each open creates a fresh panel; that is why `value` is re-supplied on every render (D2).
- **Escape with a date picker**: Escape closes the picker panel first (the popover stops there with `defaultPrevented`); the edit handler cancels only when the event is not `defaultPrevented`. Real-keyboard test (E5).
- **Window blur**: a text editor does not commit when the WINDOW loses focus (`relatedTarget === null && !document.hasFocus()`); Angular commits (html 276).
- **Blur with a rejected value** keeps the editor open with its error (Angular parity, D15); the user's text is not thrown away.
- **Editing under sort**: a commit into the sort column moves the row; the editor is already closed, focus stays on the cell index (wave 4 rule: ring stays at the screen position).
- **Group, tree, virtual**: addresses are drawn indexes (`renderedRowAt`); a collapsing group drops the editor like a page change; a virtual editor row is retained out of the window; scrolling does not close the editor.

## 4. Size
Static cost in `data-table/define.js` (gzip): package A about 2.3 KB (trigger + floating row 1.2, controller + toolbar button 0.8, glue 0.3); package B about 4.5 KB (pure edit 1.3, session 2.2, editor view 1.0). Pure filter fns and builder operations sit in the index only (about 0.8 KB there, not in define). Provisional budget: `data-table/define.js` 77 020 -> 84 000, `data-table/index.js` 77 470 -> 85 000 (both final after the integration measurement, rounded up, and justified in the PR as "wave 5: filter trigger, floating row, edit session; the builder, panels, calendar, command and date picker are lazy").
**Lazy (recommendation):** the builder (about 3 KB, loaded when the toolbar popover first opens or its trigger is hovered / focused), the three panels (about 3.3 KB, loaded with `ge-calendar` 17.7 KB / `ge-command` 14.2 KB on first use of a trigger carrying that tag), and the date editor (`ge-date-picker` 25 KB, loaded when the first `editType: 'date'` editor opens, with `focus` after `whenDefined`). The select editor is native and the checkbox editor uses the already static `ge-checkbox`, so nothing else loads. Total lazy cost is paid only by tables that use it. Do NOT lazy-load the edit session itself: Enter, F2 and the key priority rules must be synchronous.

Enter in a floating filter input opens the editor of the focused cell; Ctrl+Z in it undoes a DATA edit and `preventDefault`s the input's own undo.
- **B2** Tab on a rejected edit: cmp 4989-4995 `commitEdit()` returns silently when `validateEdit` rejects (4734), then `advanceEditToNextCell` (4998-5012) moves focus and `startEditing` replaces the pending edit: the draft and its error vanish and no event says so. Spec 4482-4555 does not pin it. (wave 4 spec already notes the rule we implement.)
- **B3** Date and checkbox editors are never focused and have no key or blur handling: cmp 4695-4701, html 233-247; the editor cannot be cancelled and never closes without a change.
- **B4** Number and select editors report strings: html 265-275 (`(input)` value) and 255-256; `editType: 'number'` hands `'5'` to `editValidator` / `valueSetter`, `newValue === oldValue` (cmp 4725) never matches a number again after typing the same digits, and non-string `editOptions` values come back as strings.
- **B5** Filter panels are not given the current filter: cmp 3846-3857, html 659-663 (see section 0.2). Check whether maintainers expect consumers to wire `selected` through `filterComponentInputs`.
- **B6** Accessible names and non-colour state missing: floating filter `ui-input` has only a placeholder (html 789-799), the builder's selects and inputs have no label (sub/filter-builder template), the active filter is shown by colour and a solid icon only (html 638-650).
- **B7** Builder link text "Clear all filters" (`clearFilters`, html 403-409) clears only the advanced filter (cmp 1126); global and column filters stay. Ambiguous (label or behaviour); D9.
- **B8** Text editor commits when the browser window loses focus (html 276 `(blur)`), e.g. alt-tab; minor.

## 9. Decisions (owner's input needed; recommended defaults)
- **D1** Filter surface: Angular parity (trigger only for `enableFiltering` + `filterComponent`; no `filterType` shorthand; no number / boolean built-ins; the trigger also appears with a custom `headerRenderer`). Recommend yes; a `filterType: 'date' | 'date-range' | 'multiselect'` shorthand can come later as pure sugar.
- **D2** Pass the current filter to panels and floating components as `value`, every render (fixes B5). Recommend yes.
- **D3** Panels, builder, calendar, command and date picker are lazy; the three panel tags auto-load from the core on first use (a consumer imports nothing); pure filter fns are exported from the index. Recommend yes.
- **D4** Filter component contract: property `value`, event `filter-change` (`detail` = new value, `null` = no filter), table stops its propagation. Recommend yes.
- **D5** Store the value as emitted (`null` stays a key), like Angular; "active" is `!isFilterValueEmpty`. Recommend parity.
- **D6** `filterDebounce` also applies to the floating text input (default 0, so parity). Recommend yes.
- **D7** Announce results for column and advanced filters (debounced 500 ms, live count). Recommend yes (a11y, beyond Angular).
- **D8** Accessible names for floating inputs, builder controls, and `aria-label` text for the active trigger (B6). Recommend yes.
- **D9** "Clear all filters" in the builder keeps Angular's behaviour (advanced only) and its English text. Recommend parity; raise B7 with the maintainers.
- **D10** Builder uses native `select` / `input` styled by the stylesheet (Angular's markup, no nested overlay inside the popover). Recommend yes.
- **D11** NL filter box and AI fill are wave 7; wave 5 only reserves the toolbar slot. Recommend yes.
- **D12** Edit session and filter UI have no new plan controller ids; the edit logic stays inside `cell-interaction` as a session (port doc section 8). Recommend yes.
- **D13** No type-to-edit in wave 5 (Angular has none; it needs a design for IME, single-key shortcuts and screen readers). Recommend no, revisit after wave 6.
- **D14** Number editor reports numbers (`valueAsNumber`, empty -> `null`); select editor preserves the option's value type (fixes B4). Recommend yes.
- **D15** Blur with a rejected value keeps the editor open with its error (Angular); a rejected Tab does not advance (fixes B2). Recommend yes.
- **D16** Focus leaving the cell: text / number commit (parity), select / checkbox / date cancel (their value commits on change anyway), window blur commits nothing (B8). Recommend yes.
- **D17** After commit or cancel, DOM focus returns to the edited cell only when it was inside the editor. Recommend yes.
- **D18** Date editor: `ge-date-picker`, trigger focused on open, not auto-opened; the picker's own Escape closes it first. Recommend yes.
- **D19** Error message in flow below the input (row grows) in normal mode, overlaid under the cell with fixed-height virtual rows so heights stay constant. Recommend yes.
- **D20** Undo / redo keys with the text-field and outside-a-cell guards; announce undo, redo and skipped stale entries; no toolbar buttons (consumers use `canUndo` / `canRedo` and the methods). Recommend yes.
- **D21** `editComponent` contract: properties `value`, `row`, `column`, `rowIndex`, `error`; events `value-change` (detail), `change` (reads `target.value`), `commit`, `cancel`; focus through `focus()` or an inner `[data-edit-input]`; `editRenderer` gets `EditContext`. Recommend yes (settles port doc decision 4's "fixed in wave 5").
- **D22** A double click on a control inside a cell (button, link, input) does not open the editor. Recommend yes.
- **D23** Double tap: 300 ms, same cell, 10 px slop, `touch-action: manipulation` on editable cells. Recommend yes.
- **D24** `startEditing` returns whether an editor opened (Angular: void). Recommend yes.
- **D25** One combined step-0 contract PR with wave 6, then the rule of section 6. Recommend yes; it needs the wave 6 author to confirm the table of section 6 before it is written.
