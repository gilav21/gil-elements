### J9 Contract changes from review round 1 (they amend J1 to J8)
- **Retained row and drag CSS:** the drag rule is `[data-draggable]:not([data-retained])`, so a retained focused row stays `position: absolute` whatever the order of the region files.
- **Rows are draggable only when the drag part handles drags:** new `RowDragService.active()` (the step 0 shell answers false; wave 6 C answers true once its part is attached). `stateView` emits `draggable`, `data-draggable`, `data-dragging` and the drop-edge child only then.
- **Range value lives in the shell:** `RangeSession` holds the range between the part's lives. `setRange` before the part is loaded (or between attach and load) and a range kept across a detach and attach are handed to the next `RangePart` through `part.setRange(...)` (round 30: ONCE, right AFTER it attaches, not before), and read back with `part.getRange()` before it is disposed. The part contract for wave 6 A: keep `getRange()` and `setRange()`. The element's `earlyRange` stays: it covers only a value set before the controllers exist.
- **One implementation per pair:** the shell's `cellRange()` and `isCellSelected()` are derived from `rangeService.range()` and `isInRange()` (`isCellSelected` = in range, else the focused cell). Wave 6 A implements `rangeService`. `RangeService.edgeOf(rowIndex, columnKey)` replaces the edge computation in `stateView`; the pure `rangeEdges(range, rowIndex, col)` is in `data-table-range.ts` for it to call.
- **Lazy failures are latched:** `lazyPart.sync(true)` after a failed load does nothing (no re-import, no second log) until the flag turns off, or `dispose()` (the next attach). The dead `loading` state is gone.
- **Diagnostics snapshot:** `sortState` and `multiSortState` enter it only with `enable-row-drag` and `local-reorder` on (the one check that reads them), so a sort no longer re-runs the config check and the O(rows) id scan.
- **`stateView` allocates nothing in range mode without a range:** shared frozen objects for the out-of-range cells (`OUT_OF_RANGE_FLAGS`, `OUT_OF_RANGE_EDITABLE_FLAGS`); the row id and the disabled flag are computed once per row, not per cell.
- Removed unused exports `CellSessionFactory` and `KeyOwner`; the five `copy*ToClipboard` element methods share one private helper.

**Round 2 (amends the above):**
- **The part's range is authoritative while a part is attached** (`part ? part.getRange() : held`, so a part that cleared its range stays cleared, also at detach). The shell reads it back at EVERY update and at detach, so no dispose can leave a stale `held`.

## 3. Design

### 3.1 Packages' internals
**FilterUiController** (`data-table-filter-controller.ts`, id `filter-ui`, provides `filters`). Owns no model state (the model owns `columnFilters` / `advancedFilter`); it draws the toolbar trigger and badge, holds the popover open state of the builder, subscribes (internal origin only) to `columnFilters` and `advancedFilter` for the debounced announcement (cancelled on detach; reads `query.filteredCount()` when the timer fires: the wave 4 lesson), and prefetches the lazy panels on `pointerenter` / `focusin` of a trigger (and again on open). It never imports another controller.
**`data-table-grid-filters.ts`** draws the header trigger and the floating row from `GridView.filters`; the trigger markup is a plain `button` so `ge-popover-trigger` can wrap it; every control keeps `tabindex` natural (header controls are tab stops, as the sort buttons are).
**EditSession** (`data-table-edit-session.ts`, package B) owns `editing`, `error`, `draft`, `editingRowId`, a double-tap detector and its own key and pointer handlers; `hostUpdate` runs `reconcileEditor(state, rows, getId)` from `data-table-edit.ts` (pure, node-tested: follows the row, drops it silently, keeps an empty list as is, moves the error with the editor) and publishes `retain('edit', ...)`. **`data-table-grid-edit.ts`** draws the editor for `GridView.edit.cell` and sets `aria-invalid` / `aria-describedby`; the error id is `ge-dt-<uid>-edit-error`.
**Pure modules** (node): `data-table-filters.ts` (the three `*FilterFn`, `isActive`, `hasFloating`, builder tree operations, multiselect toggle / select-all / clear with Angular's semantics) and `data-table-edit.ts` (`reconcileEditor`, `decideCommit` (unchanged -> cancel, repeated rejection -> stay, else write), `tabTarget`, `coerceDraft(kind, raw, options)`, `createDoubleTap`, `historyKey(event)`).

### 3.2 Locale keys (step 0, en only; every key has an interpolation noted)
`filterColumnActive` ("Filter {column}, filter applied"), `filtersClearedAnnouncement`, `filteredRowsAnnouncement` ("{count} rows match the filters"), `filteredRowOneAnnouncement`, `invalidValue` ("Invalid value"), `editCell` ("Edit {column}", the editors' accessible name), `undoAnnouncement`, `redoAnnouncement`, `historyStaleAnnouncement` ("{count} changes skipped: their rows or columns no longer exist"); optional keys on `FilterBuilderLabels` with English fallbacks: `columnLabel`, `operatorLabel`, `valueLabel`, `groupLabel` (accessible names the Angular builder lacks, B6). The panels take Today / Clear / presets from `CALENDAR_LOCALES`.

### 3.3 Details that decide behaviour
- **Selection of the active popover content**: `ge-popover-content` is not rendered while closed, so each open creates a fresh panel; that is why `value` is re-supplied on every render (D2).
- **Escape with a date picker**: Escape closes the picker panel first (the popover stops there with `defaultPrevented`); the edit handler cancels only when the event is not `defaultPrevented`. Real-keyboard test (E5).
- **Window blur**: a text editor does not commit when the WINDOW loses focus (`relatedTarget === null && !document.hasFocus()`); Angular commits (html 276).
- **Blur with a rejected value** keeps the editor open with its error (Angular parity, D15); the user's text is not thrown away.
- **Editing under sort**: a commit into the sort column moves the row; the editor is already closed, focus stays on the cell index (wave 4 rule: ring stays at the screen position).
- **Group, tree, virtual**: addresses are drawn indexes (`renderedRowAt`); a collapsing group drops the editor like a page change; a virtual editor row is retained out of the window; scrolling does not close the editor.

## 4. Size
Static cost in `data-table/define.js` (gzip): package A about 2.3 KB (trigger + floating row 1.2, controller + toolbar button 0.8, glue 0.3); package B about 4.5 KB (pure edit 1.3, session 2.2, editor view 1.0). Pure filter fns and builder operations sit in the index only (about 0.8 KB there, not in define). Provisional budget: `data-table/define.js` 77 020 -> 84 000, `data-table/index.js` 77 470 -> 85 000 (both final after the integration measurement, rounded up, and justified in the PR as "wave 5: filter trigger, floating row, edit session; the builder, panels, calendar, command and date picker are lazy").
**Lazy (recommendation):** the builder (about 3 KB, loaded when the toolbar popover first opens or its trigger is hovered / focused), the three panels (about 3.3 KB, loaded with `ge-calendar` 17.7 KB / `ge-command` 14.2 KB on first use of a trigger carrying that tag), and the date editor (`ge-date-picker` 25 KB, loaded when the first `editType: 'date'` editor opens, with `focus` after `whenDefined`). The select editor is native and the checkbox editor uses the already static `ge-checkbox`, so nothing else loads. Total lazy cost is paid only by tables that use it. Do NOT lazy-load the edit session itself: Enter, F2 and the key priority rules must be synchronous.
