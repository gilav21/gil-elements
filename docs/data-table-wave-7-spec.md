## 0. What the reading changed (read first)

1. **The xlsx writer already exists in gil-elements.** `packages/elements/src/file-viewer/parsers/xlsx.ts` (235 lines, 9.4 KB) is a byte-for-byte vendored copy of Angular's `lib/parsers/xlsx.ts` (only a `// @ts-nocheck` line added), used today only by the file-viewer test fixtures. Its reader (`xlsx-reader.ts`) and a zip reader (`zip-reader.ts`: `readZip`, `listZipEntries`) are there too. The port doc's "port `lib/parsers/xlsx` (how large?)" is answered: **no port, a move** to `shared/xlsx.ts`. The writer is a STORE-only zip (CRC32 table, no deflate, no dependency), 7 parts, all cells as shared strings. Gzip of the unminified source is 2.4 KB; minified about 1.6 KB. That is far under the 6 KB threshold of port doc 6.5-3, so **no lazy chunk**: it is statically part of the export addon. (A lazy chunk would also be invisible to the size gate: `scripts/size.mjs` skips `chunks/*` and does not follow `import()`.)
2. **The addon infrastructure is a kit, not yet wired.** `AddonSet`, `defineAddon`, `createAddonHost`, `createAddonsService` and the `addon-host` plan entry exist with node tests, but the element does not use them: no `use()`, no `addons` attribute, no `addonOptions`, no addon registry, no `addon-host` controller (`DEFAULT_ORDER` lists it, `data-table-factories.ts` has no factory), `hasActions` is hard-coded `false` (`data-table-columns-controller.ts:31`), and the grid draws no kebab buttons. Step 0 below does the wiring; without it no addon can run.
3. **The addon host cannot yet do what the Angular addons do.** It has no `root` (the context menu must listen on the table), no `emit` (addons fire `row-context-menu` etc.), no `announce`, no way to expose an imperative API (Angular's `exportAs: 'uiDtExport'` / `uiDtPivot` template references), and `DataTableAddonServiceKey` is only `query | columns | interaction`. Step 0 extends it.
4. **AI is core (owner decision 7.3), and the Angular "AI fill" has no UI.** `aiFillColumn(key, prompt)` is a method (cmp 4902); the only AI UI is the toolbar NL box (html 367-382). So "AI fill UI" is not parity; see D6. The port doc's `/data-table/addons/ai` entry (3.5) is superseded by 7.3: there is **no `addons/ai` entry**; the work is an `AiController` (plan id `ai`, already in `DEFAULT_ORDER`) plus a toolbar fragment, both in core.
5. **Pivot needs no host override** (port doc 8: Angular's pivot swaps nothing, `getPivot()` only). The brief and 6.5-7 asked for `host.setOverride`; section 8 wins, the override is decision D3 (default: not in wave 7).
6. **Context menu has no copy/paste/edit items in Angular**; the built column menu is sort / pin / hide / show-all, the row menu is whatever the consumer's `rowActions` returns. So the wave 5 and 6 dependencies are only the touch-hold arbitration in custom mode (needs range and editor state) and the optional extras (D8). Everything else can be built and fully tested now.
7. **Angular's "keyboard reachable" claim does not hold there** (cmp never moves DOM focus to a cell, so a keyboard `contextmenu` targets the scroller and `closest('[data-row-index]')` is null, context-menu.directive.ts:212-214). With wave 4's roving tabindex the target is the cell, so it works in our port, but the position of a key-initiated event is browser-dependent: we compute it ourselves (A.3).

## A. Context-menu addon (`addons/context-menu`)

### A.1 Angular behaviour (`addons/context-menu/context-menu.directive.ts`, 362 lines; spec 1107 + table spec 191)
- Two modes chosen by what is bound (docs 58-71). **Simple:** `rowActions(context) => items` plus `enableColumnMenu`; the addon registers a cell kebab and a header kebab through the host slot registries (122-148) and builds the menus itself. **Custom:** `contextMenu` is the consumer's `ui-context-menu`; gestures open it with the row (tree row merged in) or, with `contextMenuRowsOnly=false`, the header as its data (237-267). With both bound the gestures open the custom menu and the kebabs open the built one; with neither no gesture is taken. `contextMenuDisabled` hands every gesture back to the browser (kebabs unaffected).
- Gestures through `onContextGesture` (right click, context-menu key, one-finger long press, platform echo swallowed; `lib/touch`). Built column menu: sort asc/desc (disabled when current), clear sort, pin left/right/unpin, hide (omitted when `enableHiding === false`), show all (306-350); sort items omitted when `enableSorting === false`; labels from the table locale with English fallbacks.
- Custom mode and range selection (110-115, 207-226): a touch hold opens the menu only on a cell that is already selected (in the range, or the focused cell with no range) or on a header or table-owned column; on an unselected data cell the hold belongs to range selection. "Selected" is decided at `touchstart`, not when the timer fires (875 spec). Skipped while a cell is being edited.
- Outputs: `rowMenuOpen(context)`, `columnMenuOpen(column)`, `rowContextMenu({row,index,event,depth,isLeaf,parentRow})`, `headerContextMenu({column:{id,name,element},event})`.
- Compat guard (194-204): a newer addon next to an older table; irrelevant here (one package).

### A.2 Lit design
- **Entry:** `data-table/addons/context-menu` (`index.ts`: `contextMenuAddon`, option and event types; `define.ts`: `import '../../../context-menu/define.js'` then `registerDataTableAddon(contextMenuAddon)`). Id `context-menu`. Built with `defineAddon<ContextMenuOptions>('context-menu', ({ host, options, life }) => ...)`.
- **Options** (property-only, via `addonOptions['context-menu']` or `use(contextMenuAddon, options)`): `rowActions?: (context: RowActionContext<T>) => ContextMenuItem[]`; `columnMenu?: boolean`; `menu?: GeContextMenu | string` (custom mode: an element, or a selector resolved against the table's root node at open time); `disabled?: boolean`; `rowsOnly?: boolean` (default true); `locale?`. `ContextMenuItem` is `ge-context-menu`'s own type (`label`, `shortcut`, `disabled`, `type`, `children`, `variant`, `click`); it has no `icon`, so Angular's `icon: 'arrow-up'` fields are dropped (not parity-relevant: the Angular menu draws them, see D9).
- **Menu element:** the addon creates one `ge-context-menu` per open kind (row, column) lazily, appended to `document.body` (not inside the light-DOM table: lit owns the table's children), `dir` copied from the table's computed direction, `inheritThemeTokens(host.root, menuEl)` on every open (as Angular, 292/300), removed on teardown. Focus return to the opener is already done by `ge-context-menu-content` (`returnFocusTo`); the test asserts it.
- **Gestures:** `onContextGesture(host.root, handler)`; the handler resolves the row with `rowAddressOf` / `cellAddressOf` (DOM protocol, no selector copy), the row through `query.renderedRowAt(index)`, the tree row through `renderedTreeRowAt(index)`, the context through `query.rowContext(row, index)`. Header: `closest('[data-slot="data-table-head-cell"], [role="columnheader"]')` (stamped by wave 3; check the slot name in `data-table-grid-head.ts`), id from `data-column-id`. Table-owned columns (`_selection`, `_expander`, `_actions`) do not move focus. Custom mode and simple mode both focus the cell under the gesture (`interaction.focusCell`); Angular does it only in custom mode (cmp-level inconsistency, B5).
- **Keyboard (beyond Angular, A.3):** a capture `keydown` listener on `host.root` for `ContextMenu` and `Shift+F10` on a cell, row or header control sets a `keyboardOrigin` flag for the next `contextmenu` event (cleared after one task) and the handler anchors the menu at the focused cell's rect (`inset-inline-start`, bottom; mirrored in RTL) instead of the event coordinates, which browsers set differently for key-initiated events. Without the flag a `contextmenu` with `clientX === clientY === 0` and no pointer is treated the same.
- **Custom-mode hold arbitration:** `touchstart` (passive, on root) records `rangeTakesHold = menu && interaction.rangeSelectionEnabled() && !interaction.editingCell() && cell && !tableOwned(cell) && !interaction.isCellSelected(row, col)`; the gesture handler returns `false` when `viaTouch && rangeTakesHold`. Until wave 6 `rangeSelectionEnabled()` is false and `isCellSelected` is the focused cell only, so every hold opens the menu (the Angular behaviour with range selection off, spec 860).
- **Kebabs:** `host.registerCellAction({ id: 'context-menu', icon: KEBAB_SVG, ariaLabel, onClick })` when `rowActions` is set, `registerHeaderAction` when `columnMenu`; the menu opens at the button's bottom-inline-end / bottom-inline-start (`getBoundingClientRect`, null rect opens at the button's own position, not (0,0), B5). `aria-haspopup="menu"` and `aria-expanded` mirrored by the core's action button from the slot (extend `CellActionSlot` with optional `haspopup?: 'menu'`, step 0 item 6).
- **Events:** `host.emit('row-menu-open' | 'column-menu-open' | 'row-context-menu' | 'header-context-menu', detail)`, same payloads as Angular (types exported from the entry, augmenting `DataTableAddonEvents`).
- **Built column menu:** reads `query.sortDirection`, `columns.pinOf`, `host.resolvedLocale` keys that already exist (`sortAscending` ... `showAllColumns`); calls `query.changeSort`, `columns.setPin`, `columns.setVisible`, `columns.showAll`. The "hide" item is also omitted when it would hide the last visible data column (wave 4 D12).
- **Locale:** none of its own beyond reusing the table's keys; kebab labels are the two core keys of step 0.

### A.3 Edge cases to pin
Right click on the header, a group header row, a detail row, the footer, the empty row and a spacer (no `data-row-index` or no data row: open nothing, let the browser menu through, notes on the real-table spec 1-191); right click on an editor input (leave to the browser, wave 5); a long press whose platform `contextmenu` echo follows (opens once, emits once: `onContextGesture` guarantees it, test with real touch); scroll closes the menu (`ge-context-menu` does) so virtual scroll under an open menu is a close, not a stale menu; the table removed while the menu is open (teardown removes the element); two tables on one page with separate menus; `disabled` toggled at runtime; `menu` swapped or cleared (spec 988); RTL placement.

## B. Export addon (`addons/export`)

### B.1 Angular behaviour (`addons/export/export.directive.ts`, 116 lines; `lib/parsers/xlsx.ts`, 234; spec 318 + 118)
- `exportToCsv(filename?, customData?)` and `exportToExcel(...)` (44, 62): `setBusy(t.exporting)`, rows from `resolveRows` (77): `customData`, else the `exportDataProvider(host.queryState())` (server mode, all pages), else `getSortedRows()` = filtered and sorted rows across every page; grid from `host.getExportData(undefined, rows)` = visible data columns (never `_selection/_expander/_actions`), header row, each cell `col.cell(row)` or the stringified value. CSV: BOM, comma, CRLF, `escapeCsvCell` = formula guard then quote (`''=x` for a literal `'=x`; plain numbers `-12` stay numeric); Blob `text/csv;charset=utf-8;`. XLSX: `generateXlsx(grid, { boldFirstRow: true })`, Blob `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`. Download: object URL, hidden `<a download>`, click, remove, `revokeObjectURL` immediately (87-96). `finally` always clears busy; a provider rejection propagates.
- The guard is not applied to XLSX (typed string cells are never formulas); correct and kept.

### B.2 Lit design
- **Entry:** `data-table/addons/export` (`exportAddon`, `ExportApi`, `ExportOptions`, `EXPORT_LOCALES`); `define.ts` imports no other element (no UI). Id `export`.
- **API** (`host.expose`): `table.addon<ExportApi>('export')` returns `{ exportToCsv(filename?, options?): Promise<void>; exportToExcel(filename?, options?): Promise<void>; toCsv(options?): Promise<string>; toXlsx(options?): Promise<Uint8Array> }`. The last two return data without downloading (testing, upload, server hand-off). `options`: `scope: 'filtered' | 'all' | 'selected' | 'page'` (default `'filtered'` = Angular; `'all'` = unfiltered `data` via `query.rawRows()`; `'selected'` = `query.sortedData()` kept where `selection.isSelected(rowId)`, so a selected row hidden by a filter is not exported, documented; `'page'` = `query.renderedRows()`), `columns: 'visible' | 'all'` (`onlyVisible`), `includeHeaders`, `rows?: T[]` (Angular `customData`), `provider?: (query) => Promise<T[]>` (also settable once in the addon options; Angular `exportDataProvider`), `sheetName?: string` (default `Sheet1`, sanitised to Excel's rules: <= 31 chars, none of `[]:*?/\`), `boldHeader?: boolean` (default true), `typedCells?: boolean` (D4, default false), `signal?: AbortSignal`.
- **Flow:** `setBusy(locale.exporting)`; rows by scope or provider (awaited); `grid = query.exportData(opts, rows)`; CSV `CSV_BOM + toCsv(grid)` from `shared/csv.ts` (exists: `escapeCsvCell`, `toCsv`, `CSV_BOM`); XLSX `generateXlsx` from `shared/xlsx.ts`; `downloadBlob`; `finally setBusy(null)`; success announces `exportDone` (`host.announce`, locale string); a thrown or rejected provider emits `export-error` `{ format, error }`, announces `exportFailed`, clears busy, and rejects the promise (Angular lets it propagate without any user signal). `export-complete` `{ format, filename, rows, bytes }` is emitted on success (new, additive).
- **Download helper** (in `export.ts`, ~12 lines): object URL, anchor appended to `document.body` (so Firefox honours the click), click, then `setTimeout(() => { a.remove(); URL.revokeObjectURL(url); }, 4000)`. Angular revokes synchronously (96), which Safari and some Firefox builds treat as a cancelled download (B1). The test stub records the click and the revoke order.
- **Filename:** `(filename || 'export')` plus the extension unless it already ends with it; `/\\:*?"<>|` and control characters replaced with `_` (the browser would do it anyway, but the recorded name must be predictable).
- **`shared/xlsx.ts` correctness fixes** (kept compatible with the existing round-trip tests): XML 1.0 illegal characters (`U+0000-0008, 000B, 000C, 000E-001F`, lone surrogates, `FFFE/FFFF`) stripped in `escapeXml` (Excel shows a repair prompt otherwise, xlsx.ts:25); `<t xml:space="preserve">` when a string has leading or trailing whitespace or a newline (Excel trims it otherwise, xlsx.ts:96); cells longer than 32 767 characters truncated, grids beyond 1 048 576 rows or 16 384 columns throw a typed `RangeError` (Excel refuses the file); `sst count` = references, `uniqueCount` = unique (Angular writes unique in both, 96); a valid DOS date/time in the zip headers instead of `0` (xlsx.ts:121-168 writes 0, which tools show as 1980-00-00); `sheetName` option and `<cols>` skipped (no width guessing in wave 7). `typedCells` writes `t="n"` for numbers, `t="b"` for booleans, ISO dates as serial numbers with a date style, only for columns without a `cell()` formatter; it needs `query.exportData` to optionally return raw values (`exportRawData`, step 0 candidate; defaults off so this is not in the critical path).
- **Locale** (`export-locale.ts`, `en` only, rule 6.1): `exporting`, `exportDone`, `exportFailed`. `EXPORT_LOCALES` is a plain mutable object `{ en }` so wave 8's locale modules add `he` etc. with `registerAddonLocale(EXPORT_LOCALES, 'he', {...})` (a 3-line helper added to `shared/addon-locale.ts` in step 0); Angular ships en and he in the addon, the he string moves to the wave 8 module.

- **Follow-up from the step 0 review (PR #76), package B:** the moved `shared/xlsx.ts` still writes `<t>` without `xml:space="preserve"` and does not strip the XML-1.0-illegal control characters; both are B's (see the corrections above), not step 0's.

### B.3 Edge cases to pin
Server mode (`local-pagination=false`) without a provider exports only the loaded page (document it; Angular same); empty table (header only; XLSX with one row; no download of a 0-byte file); tree mode (exports `sortedData()` as flat rows like Angular; the order is the flattened tree order, indentation not exported, D10); group mode; column with `cell()` throwing (cell becomes empty, export continues, one `export-error` is not raised, a console warning is); formula-looking cells in CSV vs XLSX; very large export (100k rows x 10 cols: CSV string build stays under ~150 ms; XLSX builds in memory, documented limit; yields to the event loop every 5k rows so the busy overlay paints); concurrent calls (second call while busy returns the same promise); aborted signal clears busy without a download.

### B.4 Tests

## D. AI (core: `AiController`, toolbar NL box, `aiFillColumn`)

### D.1 Angular behaviour
- Provider contract (`shared/ai.ts`, already in gil-elements; Angular's `AiProvider` is an Observable version): `(request: AiRequest) => string | Promise<string> | AsyncIterable<string>`, `request = { task, input, prompt?, context?, signal? }`; `runAiTask` normalises to an async iterable whose emissions are the full text so far; the **last emission is the answer**. Tasks used here: `'nl-filter'` and `'table-fill'` (both already in `AiTask`). No keys, no network code ship in gil-elements: the consumer's function calls whatever model it likes (a server route holding the key is the recommended shape; documented, with a CORS-free same-origin example).
- NL filter (cmp 1059-1085, 4881-4896; html 367-382; `parseNlFilterSpec` utils 16-50, ported in wave 1 as `data-table.utils.ts:157`): shown only with `aiProvider` set, `enableNlFilter` (default true) and a visible toolbar; Enter in the box runs `runAiFilter`; request `{ task: 'nl-filter', input: query, context: { columns: [{ key, header }] } }`; the answer is JSON parsed by `parseNlFilterSpec` (a string `globalFilter`; `columnFilters` only for known keys, own-property safe); emits `nl-filter { query, spec }`; sets `globalFilter` if the spec has one and `columnFilters` if it has any. Blank query or running = no-op; `aiFilterRunning` disables the box.
- `aiFillColumn(columnKey, prompt)` (4902-4921): no-op without a provider or when the column has no `valueSetter`; for each FILTERED row, sequentially, `{ task: 'table-fill', input: JSON.stringify(row), prompt, context: { column: header } }`, validates (`editValidator`) and applies via `valueSetter`; emits `ai-fill-complete { columnKey, count: rows.length }`. **Not undoable** (does not go through `runAsCommand`, owner/maintainer decision, port doc 8): not promised here either.

### D.2 Lit design
- **`AiController`** (`data-table-ai-controller.ts`, plan id `ai`, already specified as `needs: [query, columns]`, `uses: [interaction]`, `reads: [locale]`; no provider key needed, it is reached through element methods). State: `running: 'filter' | 'fill' | null`, an `AbortController`, the box text. It contributes `renderToolbar()` (the NL box) and owns `runAiFilter()`, `applyNaturalLanguageFilter(query)`, `aiFillColumn(key, prompt, options?)`, `cancelAi()`.
- **NL box** (in the toolbar-start group when `aiProvider && enableNlFilter && showToolbar`): `<form role="search" data-slot="data-table-nl-filter">` with a `ge-input` (`aria-label=nlFilterLabel`, `placeholder=nlFilterPlaceholder`, `enterkeyhint="go"`) and a submit icon button (`aria-label=nlFilterApply`, touch target 44 px under `(pointer: coarse)`); `aria-busy` on the form while running and the input `readonly` (not `disabled`: a disabled input drops focus, Angular's `[disabled]` does, html 376). Submitting twice while running aborts nothing and does nothing; changing the query and submitting while running aborts the previous request (`AbortSignal` in `request.signal`) and runs the new one.
- **Apply path:** `answer = last(runAiTask(provider, request))`; `spec = parseNlFilterSpec(answer, columnKeys)`; `emit('nl-filter', { query, spec })`; if the spec is empty (`{}`), announce `nlFilterNoChange` and change nothing (Angular: nothing, spec 148); else `query.applyFilters({ globalFilter: spec.globalFilter ?? '', columnFilters: spec.columnFilters ?? {} })`: **replaces** both, so "show everything" and a follow-up query do not inherit stale column filters, resets to page 0, announces the result count through the existing filter-result announcement (Angular sets the two models directly: no page reset, no announcement, partial replace, B7). Errors: caught, `emit`s nothing, announces `nlFilterFailed`, `running` reset in `finally` (Angular lets the rejection escape the keydown handler, B8). Value-shape hardening beyond `parseNlFilterSpec` (D5): a column filter value must match the column's filter kind (text -> string; multiselect -> string[]; date-range -> `{ from, to }`; number -> finite number), otherwise it is dropped (the filter functions never see a hallucinated shape).
- **AI fill:** `aiFillColumn(key, prompt, { rows?: 'filtered' | 'selected' | 'page', concurrency?: number, signal? })`, default `rows: 'filtered'` (Angular), `concurrency: 1` (sequential like Angular; providers often rate-limit; D6). Requires `valueSetter`. Per row: `request.input = JSON.stringify(row)` (documented: the whole row goes to the consumer's function, so a consumer must project columns inside it if some are sensitive; option `inputColumns?: string[]` projects for them), validated and written through **`host.writeCells(requests)` in batches of the concurrency** (the cell-write channel validates, calls `valueSetter`, and fires `cell-edit`; `runAsCommand` is deliberately NOT used: not undoable; each rejected value counts into `rejected` and is not written). Progress: `setBusy` is NOT used (the table stays usable); a polite announcement every 10% and at the end (`aiFillRunning`, `aiFillDone`), `aria-busy` on the table, `ai-fill-progress { columnKey, done, total }` events at most every 250 ms. Cancel: `cancelAi()` and `signal`; a provider rejection stops the run, keeps what was written, emits `ai-fill-complete { columnKey, count, rejected, failed: true, error }` (Angular: partial fill and no event, B6). `count` = cells written (Angular: `rows.length` even when validation rejected some). The `rowIndex` passed to the validator is the rendered index of the row when it is on the page, else `-1` (Angular passes the index into the filtered list, which is not an address on the table, B6).
- **UI for fill** (none in Angular): none in wave 7 (D6). The method, event and docs are the feature. A prompt popover on the column menu is a follow-up that needs only `host.registerHeaderAction`.
- **Size:** NL box + controller ~220 lines source, about 1.3 KB gzip in the core `define.js`; the NL box markup is behind `aiProvider` so there is no runtime cost without a provider. The alternative the port doc proposed (a lazy `addons/ai`) was dropped by decision 7.3.

### D.3 Edge cases to pin
Provider returns an empty string, non-JSON, JSON with unknown columns, `__proto__` keys, a huge object; async-iterable provider emitting progressive text (only the last emission is parsed); provider that never resolves (cancel on disconnect, on new query, and a 60 s default timeout through `AbortSignal.timeout`, option `aiTimeout`); table disconnected mid-fill (abort, no writes after, no unhandled rejection); `data` replaced mid-fill (rows resolved by id before each write; a vanished row is skipped and counted `skipped`); `valueSetter` returning a new row object (the cell-write channel handles it); server-mode table (`local-filtering=false`): the NL result only updates the models and fires `query`; two quick Enter presses; IME composition Enter (`isComposing` ignored); RTL toolbar order.

### D.4 Tests
Node (`data-table-ai.node.test.ts`, fake host and provider, no DOM): Angular `data-table-ai.spec.ts` ports: `parseNlFilterSpec` cases 31-54 (if wave 1 did not already: check `data-table.utils.node.test.ts`), NL compile + `nl-filter` event + models (88), no-op without provider (100), blank query no-op (129), running flag reset on rejection (141), empty spec emits but leaves state (148), fill via `valueSetter` for each filtered row (105), no-op without `valueSetter` (115), validator-rejected rows skipped (158); new: request shape (`task`, `input`, `context.columns`, `signal`), last-emission semantics of an async iterable, abort on a second query, `AbortSignal.timeout`, replace-both semantics, page reset, shape hardening per filter kind, fill batching with concurrency 1 and 3 (order of writes preserved), cancel keeps prior writes, failure event, disconnect cancels, progress throttle (fake timers), `inputColumns` projection.

## J. Candidate Angular bugs found (verify against Angular first; do NOT file from this spec)
- **B1** `export.directive.ts:87-96` `URL.revokeObjectURL(url)` runs synchronously right after `a.click()`: Safari and some Firefox builds then cancel or fail the download. Also the anchor is appended after `document.body` access without a connected-check (fine) and the error path leaves a rejected promise with no user-visible signal (77-88 propagate).
- **B2** `lib/parsers/xlsx.ts:25` `escapeXml` does not remove XML-1.0-illegal control characters (Excel reports a corrupt file); `:96` `<t>` lacks `xml:space="preserve"` (leading/trailing spaces and newlines lost); `:110` every value is a shared string, so numbers export as text ("number stored as text", `SUM` fails); no 32 767-character or 1 048 576-row guard; `:96` `count` equals `uniqueCount`; zip headers carry date/time 0 (`:121-168`).
- **B3** `context-menu.directive.ts:131, 143` kebab `ariaLabel` are hard-coded English (`'Row actions'`, `'Column menu'`); `cmp html 608` the `_actions` header text `Actions` is hard-coded too (the locale has `actions`, check use).
- **B4** `context-menu.directive.ts:212-214, 260`: the docs promise the context-menu key, but with no DOM focus on a cell (focus is a signal on a `tabindex=0` scroller) the key's `contextmenu` target is the scroller, `closest('[data-row-index]')` is null and nothing opens. Verify in a real browser; if confirmed it is the same root cause as issue #267's focus half.
- **B5** `context-menu.directive.ts:243` only custom mode focuses the cell under the gesture (simple mode `openBuiltRowMenu` 228-235 does not); `:281-286` a null button rect opens the menu at (0,0).
- **B6** `cmp 4902-4921` `aiFillColumn`: awaits sequentially with no abort, progress or concurrency control; a provider rejection mid-run leaves a partial fill and no `aiFillComplete`; `count` is `rows.length` even when `validateEdit` rejected rows; the `rowIndex` given to `validateEdit` is the index into `filteredData()`, not a rendered address (wrong when paged); `JSON.stringify(row)` leaks the whole row to the provider with no projection option.
- **B7** `cmp 4881-4896` NL filter sets `globalFilter`/`columnFilters` directly: no reset to page 0 (compare the handlers at 3522, 3538), no result announcement, and a spec without `columnFilters` leaves the previous column filters in place (a follow-up "show everything" query cannot clear them). Verify with a table on page 2.
- **B8** `cmp 1077-1085` `runAiFilter` has `try/finally` without `catch`: a provider rejection becomes an unhandled rejection from the `keydown.enter` handler and the user sees nothing.
- **B9** `utils 16-50` `parseNlFilterSpec` validates column keys but not value shapes; a model-invented `{ "date": 5 }` reaches the date filter function.
- **B10** `data-table-range-chart.component.ts:74-80` bar and pie silently chart only the first series (no indication which); negative values break the pie; `html 15` prints raw `bar|pie|stacked`; `:67` default title `Chart` is English; the canvas has no accessible name or data table.
- **B11 (question, not a defect)** `pivot.directive.ts` pivots the raw `data` (ignores filters); if intended, say so in the docs; ours keeps it and offers `getPivot` over any rows (option `rows`).

## K. Decisions (recommended defaults; Angular parity first)

- **D1. Addon entries import no element.** `registerDataTableAddon` module instead of `GeDataTable.registerAddon` (RTE style). Default: yes; it keeps every addon `define.js` free of the 77 KB core.
- **D2. Addon API exposure.** `host.expose(api)` plus `table.addon<A>(id)`. Default: yes (stands in for Angular `exportAs`).
- **D3. Pivot override on the host** (`setOverride({ columns, data })` with reset, per port doc 6.5-7). Default: **no** (section 8: Angular's pivot swaps nothing; a host override needs rules for edits, selection ids and `data-change` on a pivoted view). Revisit if the owner wants a one-line "pivot this table" UI; cost ~60 core lines.
- **D4. XLSX typed cells** (`typedCells`: numbers, booleans, dates). Default: option present, **off** (parity: all strings); recommend turning it on by default in a later wave once a formatted-number story exists. The writer corrections (control chars, whitespace, limits, zip date) are on, since they only fix corrupt or lossy output.
- **D5. NL filter replaces both filter records, resets to page 0, announces, and validates value shapes.** Default: yes (fixes B7-B9); the Angular partial-replace behaviour is not kept.
- **D6. AI fill:** method + events only, sequential (`concurrency: 1`), no UI, not undoable (consistent with maintainers' decision). The brief's "AI fill UI" does not exist in Angular; default: no UI in wave 7, prompt popover as a follow-up. Progress events and cancel are additions.
- **D7. Range chart series picker and accessible data table.** Default: yes (beyond Angular, small).
- **D8. Default copy/paste/edit items in the built row menu.** Default: no (Angular has none; consumer `rowActions`); revisit after wave 6 as an option `defaultItems: ('copy-cell' | 'copy-row' | ...)[]`.
- **D9. Menu item icons.** `ge-context-menu` items have no `icon`; Angular draws them. Default: no icons (document); adding an `icon` slot to `ge-context-menu` is a separate change to that element.
- **D10. Export of tree and grouped tables.** Default: parity (`sortedData()` flat, no indentation or group rows); a `scope: 'visible-tree'` is a follow-up.
- **D11. Row kebab buttons `tabindex=-1`, keyboard via ContextMenu / Shift+F10; header kebabs tabbable.** Default: yes (one tab stop per grid, wave 4). Alternative: tabbable kebabs (Angular), at one extra tab stop per row.
- **D12. Toolbar export button / menu** (Angular has none; export is method-only). Default: none; a `registerToolbarAction` slot would be the way if wanted.
- **D13. Export `scope: 'selected'` order** is sorted-filtered order and excludes selected rows hidden by a filter. Default: yes (documented), since `rowSelection` keeps stale ids by design (section 8).
- **D14. Step 0 by the lead first** (grid, host, providers, registry, locale and packaging plumbing); the four packages cannot run in parallel without it.
