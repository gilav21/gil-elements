## 0. What the reading changed (read first)

Corrections to `data-table-port.md` and to what the task list assumed. Each one has a consequence further down.

1. **Angular has no shift extension for ROW selection and no click-the-row selection at all.** The row checkbox toggles (`toggleRow`, cmp 3335; `toggleRowWithCascade`, 5265, via html 112). Shift is used for (a) extending the CELL range with shift+mousedown (cmp 4351-4366, wave 6) and (b) multi-sort on a header click. Ctrl/meta never select rows (notes part 4 section 7). There is also no "single selection" mode. So "shift range extension" for rows is a Lit-only addition (decision D1); parity is checkbox-only.
2. **Angular arrow keys are NOT flipped in RTL.** `isRtl()` (cmp 317) is read only for the fill-handle position (2809) and the resize delta (6242, 6276). Port doc 6.4 is wrong on this. Flipping Left/Right in RTL is our decision (D4), not parity.
3. **Angular traps Tab inside the grid** (`Tab` is in `navKeys`, `handleNavigationKeydown` cmp 4624-4660 calls `preventDefault`, `computeTabTarget` returns the same cell at the last cell): a keyboard trap (WCAG 2.1.2). Specs 4329-4362 pin it. We do not copy it (D3).
4. **Angular never moves DOM focus to a cell.** `focusedCell` is a signal; the ring is a class; real focus stays on the one `tabindex=0` scroller (that is issue #267's second half). Our roving tabindex means real `cell.focus()`, so scrolling, sticky header / pinned overlap and focus loss under virtual scroll become OUR problems (section D).
5. **The header select-all covers ALL filtered rows across pages**, not the page: `selectableRowIds` over `filteredRowIds` (cmp 1717: `filteredData()` ids, or `visibleTreeRows()` ids in tree mode); disabled rows excluded; selections made under an earlier filter survive (spec 545 "preserve off-filter selection"). Wave 3's `headContent` (`data-table-grid.ts`) computes it from `v.rows` (the page). Wave 4 replaces that with the selection service.
6. **`aria-rowindex` and `data-row-index` are two different counters.** `data-row-index` is the DRAWN data index (group headers and detail rows not counted). `aria-rowindex` counts every real row (header rows, group header rows, detail rows, data rows, footer). Wave 3's `dataRow` passes the data index to `aria.dataRowIndex(i)`, which is only right while no group / detail row exists. Wave 4 must keep a second running ordinal in the renderer.
7. **Grouping is inactive under virtual scroll and under tree mode** (cmp `groupingActive`, wave 1 `isGroupingActive`), specs 3370 / 3381. So virtual windows never contain group headers; the window slices `sortedData` or `visibleTreeRows` only. The element's `role="treegrid"` for `groupBy` (wave 3 decision 4) stays, even while grouping is switched off by a conflict.
8. **Angular writes `columnWidths` on every pointermove** (cmp 6271-6286), so a consumer sees one `column-widths-change` per pixel of drag. Our drag writes one CSS custom property and commits once on release (section E).
9. **The Angular repo is 5 commits past the notes.** `509257d8` ("a row selected at creation now shows as selected") and `c1d57209f` (#267 selection half: `aria-selected` on rows, `aria-multiselectable` on the grid; #269 `buildTreeFromFlat` keeps every row once, which wave 1 already has). Angular now stamps the selection semantics too, so those are parity, not "beyond Angular"; the focus half (roving tabindex) is still ours. The lead should re-run the Angular diff (`git log 99bf6c06..HEAD -- packages/components/ui/data-table`) before wave 4 closes and mirror any new spec in `data-table-grid-semantics.spec.ts`.
10. **Wave 1 already has most of the maths** (`data-table-virtual.ts`: `computeRowRange`, `computeColumnRange`, `computeVariableRowRange`, `buildPrefixSums`, `isVirtualScrollActive`, `columnMinWidthPx`; `data-table-tree.ts`: `flattenTree`, `buildTreeIndex`, `filterTree`, `sortTree`; `data-table-group.ts`; `data-table-view-state.ts` column reducers; `data-table-range.ts`). Wave 4 is controllers, renderers, DOM wiring and real-browser tests, not new algorithms (two exceptions: sibling position for `aria-posinset`, section B; a column-order reducer, section E).

## A. Selection

### A.1 Angular behaviour
- State: `rowSelection: Record<id, true>`; deselect DELETES the key (cmp 3335-3350). `isRowSelected` reads `!!selection[id]`.
- `toggleRow` ignores disabled rows (`isDisabled` = `isRowDisabled(row)` or id in `disabledRowIds`, cmp 3317). `selectRows(rows)` DOES select disabled rows (programmatic bypass); `unselectRows`, `clearSelection` (drops ids hidden by the filter too), `selectAll` (idempotent, skips disabled), `toggleAll` (the header action).
- Header state: `isAllSelected` = every selectable id selected (false when none selectable); `isIndeterminate` = some but not all of the selectable ids. Selectable = filtered ids minus disabled (cmp 3417-3480). Tree mode: ids come from `visibleTreeRows` (expanded nodes only, all pages).
- Tree checkbox (`treeRow ? toggleRowWithCascade : toggleRow`, html 112): mode `self` = plain toggle; `descendants` mirrors onto the whole subtree (`treeIndex().descendants`), `filteredDescendants` onto the subtree intersected with the visible ids; then `bubbleUpSelection` walks parents: parent selected iff all its children are, else key deleted. A node's checkbox is indeterminate when some but not all descendants are selected (`_indeterminateRows`, never in `self` mode).
- Stale ids are kept: nothing prunes `rowSelection` when data changes; `selectedRows` (cmp 1717 area) filters `data()` so it can be shorter than the key count. Intended (notes part 8, 6.6 #4); document it on the property and pin it in a node test.
- Pinned by (spec, notes numbering): "should handle row selection" ~493, "preserve off-filter selection when toggling all on filtered rows" ~545, disabled rows in toggleRow / toggleAll / isAllSelected ~1436-1478, "Row Selection API" ~1917, "Selection Cascade" ~2407-2628, `data-table-grid-semantics.spec.ts` (new `aria-selected` / `aria-multiselectable` cases from `c1d57209f`).

### A.2 Lit design
- **Owner:** `SelectionController` (`data-table-selection-controller.ts`, plan id `selection`, provides `selection`). It owns only `model.rowSelection` and the disabled set; no DOM.
- **`SelectionService`:** `isSelected(id)`, `isDisabled(row)`, `toggleRow(row)`, `toggleRowCascade(row)` (picks the mode), `toggleAll()`, `selectRows(rows)`, `unselectRows(rows)`, `clearSelection()`, `selectAll()`, `header(): { checked, indeterminate, selectableCount }`, `isIndeterminate(id)` (tree). All writes are `model.set('rowSelection', next)` with a NEW object (identity is the change signal), so `row-selection-change` fires from the model store once per command (the cascade builds one object, one event). A consumer assigning the property fires nothing (wave 2 semantics).
- **Pure core** (new `data-table-selection.ts`, node-tested): `selectableIds(ids, isDisabled)`, `toggleAllSelection(selection, selectable)`, `cascadeSelection(selection, id, mode, index, visibleIds)`, `indeterminateIds(selection, index, mode)` (memoised by selection identity + tree index identity), `selectionHeaderState`. Everything reads `QueryService.treeIndex()` (an id -> node / parent / children / descendants map built once per `data` / `getChildren` identity by the query stage; this is the "precomputed tree index", never `findRowById`).
- **Element public methods** (delegate): `selectRows`, `unselectRows`, `clearSelection`, `selectAll`, `toggleRow`, `toggleAll`, `selectedRows` getter (filters `data` by selection, as Angular).
- **DOM hooks** (wave 3 already stamps most): `aria-multiselectable="true"` on `[data-slot=table]` when `enable-row-selection`; per data row `aria-selected="true|false"` + `data-state="selected"`; `ge-checkbox[aria-label=selectRow]` with `.checked`, `?disabled`, `.indeterminate` (tree); header `ge-checkbox[aria-label=selectAllRows]` bound to `header()`. Checkbox `change` events are handled by ONE delegated listener on the viewport (`closest('[data-special=selection]')` -> row from `data-row-id`), never per-cell handlers. Group header rows have no `aria-selected` (they are not selectable).
- **Space on a focused cell** toggles the row's selection (APG multi-select grid), registered through `host.addKeyHandler(50, ...)` by this controller (it reads `provider('interaction').focusedCell()`, lazily; section D). Not on a disabled row, not while a cell editor is open (wave 5), not when the target is an input. Enter does not select.
- **Shift+click on the row checkbox** (D1, off by default, beyond Angular): selects every selectable row between the last toggled row (anchor id, kept in the controller) and this one, in DRAWN order, using `QueryService.renderedRows()` ids; a tree or group anchor outside the current page falls back to a plain toggle. If D1 is rejected the controller ships without it; nothing else depends on it.
- **Events:** only the model events of wave 2 (`row-selection-change`, detail = the new record). No extra interaction event. The aria-live count (section E.5) is a separate debounced announcement.
- **Disabled rows:** `data-disabled` + `aria-disabled="true"` on the row (wave 3), checkbox `disabled`, skipped by ArrowUp/Down (D), still reachable by Home / PageDown (Angular: `findNextEnabledRow` only for single steps; keep and pin).

### A.3 Edge cases to pin in node tests
Select-all when every selectable row is disabled (checked=false, nothing happens); select-all then paging keeps selecting off-page rows; stale ids stay after `data` is replaced and after the row is filtered out; `toggleAll` on a filter-reduced set leaves other selections; cascade with a filter in `filteredDescendants` mode; bubble-up deleting a parent key when one child is unchecked; a leaf whose `getChildren` returns `[]` vs `undefined`; duplicate ids (default `getRowId` safe fallback, wave 1); a model write in the same tick as a consumer property write; `rowSelection` containing `false` values written by a consumer (treated as unselected; our writes never store `false`).

### A.4 Real-browser tests (`data-table-selection.browser.test.ts`, owned by package A)
1. Click a row checkbox: `aria-selected`, `data-state`, event once with the new record; the row's own cells do not select on click.
2. Header checkbox: unchecked -> checked (all filtered rows of ALL pages, assert via `rowSelection` size, 25 rows / page size 10) -> indeterminate after unchecking one -> click header again selects all (APG behaviour of Angular's `toggleAll`: from indeterminate selects all).
3. The AX tree (`cdp().send('Accessibility.getFullAXTree', { frameId })`, pattern of `accordion.browser.test.ts:133`) exposes the grid as multiselectable and the rows as selected; a disabled row's checkbox is disabled.
4. Space on the focused cell toggles; Space inside a `ge-input` cell editor does not (wave 5 will add the case); Enter does nothing.
5. Tree cascade: 3 levels, `descendants`, then `filteredDescendants` with an active filter, indeterminate checkbox state visible in the AX tree (`checked: mixed`).
6. If D1: shift+click range down and up, across a page boundary (falls back), after a sort (drawn order, not data order).
7. Touch: the checkbox hit area is at least 44x44 under `emulateTouch` (pattern of the wave 3 / Angular `DT.browser:381`).
8. Reduced-motion and dark: tint visible on a selected non-pinned row (wave 3 decision 9).

The detail row carries `data-detail-for=<data-row-index>` and `data-row-id` of its data row so the virtual measurer (C) and `cellAddressOf` can tell it from a data row; it has NO `data-row-index` (it is not an addressable data row). ### B.2 Tree mode (`enableSubRows`)
- Angular: cmp 5020-5380 and html 1156-1247. `subRowDefaultExpanded` depth rule (explicit entry wins, `-1` = all), `getRowDepth` via the index, `subRowSelectionMode`, `subRowFilterMode` (`excludeChildren` / `includeChildren` / `includeParentOnChildMatch`), `enableSubRowSorting` (siblings only), `subRowsPaginated` (page the flattened visible rows) else page the ROOTS and flatten each page's roots with their expanded descendants (`flattenTreeRowsForPage`, 1560-1580). `activeTotalItems` in tree mode = flattened length or root count accordingly. Aria: `aria-level = depth + 1`, `aria-expanded` omitted on leaves; Angular stamps no `aria-setsize` / `aria-posinset` (ours adds them).
- Lit query stages (`QueryController`, package A): `tree = buildTree(data)` (flat->tree is the consumer's job through `buildTreeFromFlat`), `filtered = filterTree(...)` (wave 1; `excludeChildren` tests only the roots and keeps their subtrees), `sorted = sortTree(...)` (when `enableSubRowSorting`), `visible = flattenTree(sorted, {expanded, defaultExpandedDepth})`, `page = pagesLocally ? (subRowsPaginated ? slicePage(visible) : flatten(slicePage(sortedRoots))) : visible`. Each stage memoised on input identity (`memoLast`); changing `rowSelection` / `loading` / focus must not re-run any of them (identity test). `treeIndex = buildTreeIndex(data, getRowId, getChildren)` memoised on `data`, `getRowId`, `getChildren` only. `visibleTreeRows()` = the un-paged `visible` list (what virtual slices and select-all counts); `treeRows()` = the drawn page.
- **Sibling position (new, wave 1 file change by package A):** `FlattenedTreeRow` gains `setSize` and `posInSet` computed in `flattenTree` from the sibling list it is already walking (siblings of the FILTERED, SORTED tree, so a filtered-out sibling does not count; `aria-setsize` is the filtered sibling count). Needed by `aria-setsize` / `aria-posinset`; update `data-table-tree.node.test.ts`.
- DOM (wave 3 spec 1.7): row `data-depth`, `style=--ge-dt-depth:d`, `aria-level`, `aria-expanded` (omitted on leaves), `aria-setsize`, `aria-posinset`; the tree-host cell (`treeExpander` column, else the first data column; computed in `EnhancedColumnDef`, never leaked on the public type) draws `div[data-slot=data-table-tree-cell]` with a toggle `button[data-toggle]` (`expandSubRows` / `collapseSubRows` labels) or `span[data-slot=data-table-tree-leaf]`; indent through `--ge-dt-indent * depth`. The tree-host header holds the expand-all / collapse-all buttons (`isAllSubRowsExpanded`).
- Keyboard (APG treegrid, on the TREE-HOST cell only): ArrowRight (ArrowLeft in RTL) expands a collapsed node, otherwise moves; ArrowLeft (Right in RTL) collapses an expanded node, otherwise moves. Registered with `addKeyHandler(50, ...)` by `ExpansionController`. `Alt+*`/`+` is not used.
- Selection with cascade: section A. Checkbox indeterminate from `SelectionService.isIndeterminate`.
- Edge cases: orphan / cycle input (wave 1 `buildTreeFromFlat` fixed it); a node collapsed while a descendant holds focus (focus must move to the collapsing ancestor: `CellInteraction` reconciles; test it); expanding a node on the last page; `getChildren` returning a new array every call (index keyed by id, not identity); filter + sort + expand with 5k nodes under 25 ms (node benchmark); drag / reorder is wave 6.

## C. Virtual scroll

### C.1 Angular behaviour
- Cmp 795-1030 (inputs, computeds), 2130-2190 (viewport observer, scroll handler, row ResizeObserver), 6404-6460 (`scrollToRow` / `scrollToColumn` / `scrollToCell`), html 813-1155.
- `isVirtualScrollActive`: `false` never; `'auto'` is OFF whenever a pager is in play (`localPagination && showPagination`) and otherwise ON when rows > 500 or non-pinned columns > 20; `true` always (a visible pager is then inert: `pagesLocally` false). Wave 1 `isVirtualScrollActive` + `pagesLocally` already encode it; the controller feeds it `virtualTotalRows` = `sortedData().length` (flat) or `visibleTreeRows().length` (tree) and the middle column count.
- Window = slice of `sortedData` / `visibleTreeRows` (NOT of the paged list; `dd2f8156` fixed "only 10 rows scroll"). Rows `data-row-index = start + i` (`getVirtualRowIndex`). Top / bottom padding as bare `div`s of height `paddingTop` / `paddingBottom`; left / right padding as `min-width` divs INSIDE each row; pinned columns always drawn; header and footer are NOT windowed.
- Scroll: `onVirtualScroll` rAF-coalesced, writes `virtualScrollTop/Left` signals; ignored while `suppressScrollEvents`. Viewport size from a ResizeObserver on the container (`clientHeight/Width`).
- Fixed rows: `effectiveRowHeight` = `virtualRowHeight ?? (coarse ? 60 : 40)`, inline `height`. Variable rows (`virtualVariableRowHeight`): one ResizeObserver over the rendered rows, `rowHeightCache` by index, `measurementVersion`, prefix sums rebuilt, and when a measured row ABOVE the first visible row changes, `scrollTop += diff` with scroll events suppressed until the next frame; diffs under 0.5px ignored; no ResizeObserver = estimates only. History of three reverts (`7eb92725`, `9ff3c929`, `60407733`): do not use index tracking or anchor-based restoration; the condition is `index < firstVisible`.
- `scrollToRow(index)` = `scrollTop = prefix[index]` (variable) or `index * rowHeight`, unclamped; `scrollToColumn` = sum of middle widths before it (pinned / hidden target: no-op); `scrollToCell` both. Keyboard navigation calls `scrollToRow(focused)` (so the focused row jumps to the TOP) only while virtual is active.
- Pinned by: `data-table-virtual-scroll.spec.ts` (pure windows, already ported in wave 1 `data-table-virtual.node.test.ts`), spec ~5430-5557 / 5744-5914 / 5958-6160 (all with a fake `scrollTop`, a stub ResizeObserver and injected viewport size: the notes confirm no spec scrolls a real element for the window), `data-table-grid-semantics.spec.ts` 188-243 (absolute `aria-rowindex`, `aria-rowcount` = dataset, `aria-colindex` omitted), browser spec 198 (one scroller, sticky header, pinned column), 225 (`minWidth`).

### C.2 Lit design (`VirtualController`, `data-table-virtual-controller.ts`, plan id `virtual`, provides `virtual`)
- **State** (plain fields, not model): `scrollTop`, `scrollLeft`, `viewport {height, width}`, `headerHeight`, `footerHeight`, `measured` (index -> `{ row, detail }`), `prefix` (Float64Array, rebuilt on a measurement batch), `retained` (Map owner -> Set of indices). The window is recomputed in `hostUpdate()` from these via the wave 1 functions and compared with the previous (`start/end/colStart/colEnd`); `topics.emit('viewport')` and `requestRender()` ONLY when it changed. Most scroll events inside the buffer cause no render (assert in the perf test).
- **Inputs it gives the renderer:** `BodyWindow` (step 0) with `padStart/padEnd` written as the custom properties `--ge-dt-pad-top` / `--ge-dt-pad-bottom` on `[data-slot=table-body]` (CSS `padding-block`) and `--ge-dt-pad-start` / `--ge-dt-pad-end` on `[data-slot=table]`; column spacers are `div[data-slot=data-table-spacer][data-edge=start|end][aria-hidden=true]` inside each row with `inline-size: var(--ge-dt-pad-start|end)`. No per-row style binding, no vertical spacer ELEMENTS (decision D6; the wave 3 `spacer` kind stays for the trailing stretch row only). Logical properties only, so RTL needs no code; `scrollLeft` is read as `Math.abs()` (Chromium RTL scrollLeft is <= 0).
- **Middle-column windowing only** (`computeColumnRange` over `ColumnsService.enhancedColumns()` that are not pinned, width from the resolved px of `--ge-dt-col-N`: `px` read once from `getComputedStyle(table)`; `%` / `rem` widths are measured, not parsed; auto columns use `virtualAutoColumnWidth`). Window uses the raw `scrollLeft` against middle coordinates, which over-renders by the pinned-left width at most: safe, keep. Cells keep their ABSOLUTE position `n` (`--ge-dt-col-N`, `aria-colindex`), which answers the port-doc 8 question: with absolute `n` the index is always correct, so `aria-colindex` is emitted while windowed (decision D7, deviation from Angular's pinned omission; update `data-table-aria.ts` `colIndex` and its node test).
- **Host attributes:** `data-virtual="fixed|variable"` on the element (wave 3 CSS uses it for `contain: strict`, fixed row height via `--ge-dt-row-height`); `will-change`, `contain: strict` need a bounded height: with an unbounded host the viewport is 0px tall (Diagnostics warns once and the window degrades to buffer rows).
- **Row height source:** fixed mode reads `--ge-dt-row-height` once per resize from `getComputedStyle(viewport)` (wave 3 spec section 4), never from a JS constant, so coarse (60px) and consumer overrides match CSS; if the computed value is not a pixel number it falls back to the first measured row.
- **Viewport observer:** one `ResizeObserver` on the viewport + header + footer elements. The callback only stores the size and schedules a rAF; the render is requested from the rAF, never inside the observer callback (otherwise Chromium reports "ResizeObserver loop completed with undelivered notifications"). The scroll listener is `passive`, coalesced into the same rAF.
- **Variable height:** `ResizeObserver` per rendered data row AND per detail row; an entry maps to an index through `data-row-index` or `data-detail-for`; the item height is `row + detail`. Prefix sums rebuilt (O(n); fine to ~200k rows, revisit with `VirtualAxis` above that: decision D8). Compensation rule exactly as Angular (diff, `index < firstVisible`, skip < 0.5px). **`overflow-anchor: none` on the viewport in virtual mode**: Chromium scroll anchoring would apply its own correction on top of ours (never visible in Angular's stubbed specs; this is the first thing the real-browser variable-height test checks).
- **Focus retention (D, "keep the focused cell rendered"):** `retain('focus', [rowIndex])` and `retain('edit', [...])`. A retained row outside the window is rendered with the same markup, `data-retained` and `style="position:absolute; inset-block-start: var(--ge-dt-retained-top); inset-inline: 0"` where the offset is `prefix[index]` (fixed: `index * h`) relative to `[data-slot=table-body]` (`position: relative` in virtual mode). It is out of flow, so padding maths are untouched, DOM focus is never lost, and Tab / Shift+Tab can still land on the roving cell. It is dropped when the cell is blurred AND the focused cell moved, not on scroll alone.
- **Scroll API:** `scrollToRow(i)` (top-aligned: `prefix[i]`, clamped to `[0, maxScroll]`, unlike Angular), `scrollToColumn(key)` (works for any column key: pinned = no-op, as Angular), `scrollToCell`, and `reveal(rowIndex, columnKey?)` for keyboard focus: minimal scroll (`block: nearest`: above = align top, below = align bottom accounting `headerHeight` / `footerHeight`, inside = no scroll), plus horizontal for a middle column hidden behind pinned columns. `scroll-padding-top/bottom` is set from the measured header / footer height (`--ge-dt-head-h`, `--ge-dt-foot-h`) and `scroll-padding-inline-start/end` from the pinned stacks so native `scrollIntoView` and focus also respect the sticky overlay in non-virtual mode. Element methods delegate: `scrollToRow`, `scrollToColumn`, `scrollToCell`, `refresh()`.
- **`aria-rowcount` under virtual scroll** = header rows + `virtualTotalRows` (+ measured details) + footer; `firstRenderedRow` = window start; the retained row keeps its absolute `aria-rowindex`; spacers are `aria-hidden` / padding. Grouping off (B.3). Tree rows: `aria-level / setsize / posinset` come from the row, correct while windowed.
- **Recycling custom-element cells (`virtual-recycle-components`)**: ship KEYED `repeat` (by `getRowId`): a row that scrolls out is removed, a new row creates new elements; a custom element cell is reused only across data updates of the same row. Port-doc 6.5 plans the flag as a documented no-op alias unless the benchmark below fails. If it fails, the flag switches the row list to positional rendering (`items.map`, key = slot index) with a post-render refocus rule (focused cell element keeps DOM focus while its content row changes; re-assert `focus()` on the roving cell). Benchmark and the decision rule are in C.4; the flag is accepted either way.
- **Edge cases:** `data` replaced while scrolled far down (clamp scroll to the new height); filter shrinking the set below the scroll offset (scroll back, announce nothing); `sortedData` length 0 (empty state, no padding); window recomputed when the column set changes (hide / show / resize / reorder) and when the font loads (row height measured late); `contain: strict` + sticky pinned columns + `position:absolute` retained row z-order; page zoom (fractional heights: sums use floats, compare with 0.5px noise); `prefers-reduced-motion` irrelevant; detached element reconnect rebuilds observers; two tables on one page; print.

### D.1 Angular behaviour

### D.2 Lit design (`CellInteractionController`, `data-table-cell-interaction-controller.ts`, plan id `cell-interaction`; wave 4 = focus, wave 5 adds edit, wave 6 range, in the same file)
- **State** (private): `focused: CellAddress | null`; later `editing`, `range`. `CellInteractionService.focusCell(rowIndex, key)` is the only public mutator; it writes the field, `topics.emit('cell')`, `requestRender()`, then `afterRender` moves DOM focus. The reconcile step runs in `hostUpdate()` after the `rows` topic: empty list -> nothing; else clamp row to `rows.length - 1`; if the column left the layout, move to the nearest navigable; if the focused row was in a group that collapsed, move to the nearest drawn row (clamp) and announce nothing.
- **Roving tabindex (wave 3 already renders the attribute):** exactly one cell `tabindex="0"` (the focused one); the viewport `tabindex="-1"` while a cell is focused AND rendered (retained rows count as rendered), `0` otherwise. In-cell controls (`ge-checkbox` host, expander / tree toggle / actions buttons) get `tabindex="-1"` unless their cell is the roving cell, so a 10k-row grid has ONE tab stop; the mouse still works. `focusin` on the viewport itself (Tab from outside, nothing focused yet) is forwarded: focus the first cell (or the last focused). `focusout` leaving the grid keeps `focused` (Tab back returns to the same cell, ring stays).
- **Which columns can be focused:** `navigableKeys()` (data columns) stays the key list of range / copy / paste (wave 2). A second list `focusableKeys()` = navigable + `_selection` + `_expander` (not `_actions`, which holds buttons) is what arrows traverse, so the keyboard can reach the row checkbox and the detail expander (Space / Enter on those cells toggles their control). Add to `ColumnsService` in step 0 (D2).
- **Pointer:** a delegated `pointerdown` (button 0, not on `input,textarea,select,button,a,[role=checkbox]`, not in an open editor) sets the focused cell to `cellAddressOf(event.target)` and focuses it with `preventScroll`; wave 6's range controller owns the same listener when range selection is on (`data-range-selection`). Click outside any cell clears focus (Angular `onTableClick`), but a click inside a toolbar / pager / header does not clear it.
- **Key map** (one `addKeyHandler(100, ...)` registration; handlers of selection / expansion (50) run before it, clipboard (copy, paste) at 10; unmatched keys fall through to the browser untouched; handler ignores events with `defaultPrevented`, `isComposing`, targets that are editable controls, and Alt/Meta unless listed):
  - Arrow Up / Down: previous / next drawn row skipping disabled rows; crosses group boundaries and pages' ends in DRAWN order; stays on the last / first row (no page flip; a pager is a separate control). Left / Right: previous / next focusable column, FLIPPED when `getComputedStyle(root).direction === 'rtl'` (D4). The edge cell does nothing (no wrap).
  - Home / End: first / last focusable column of the row. Ctrl+Home / Ctrl+End: first cell of the first drawn row / last cell of the last DRAWN row (a collapsed group hides its rows: spec 3691). Meta on macOS counts as Ctrl, as Angular.
  - PageUp / PageDown: move by `max(1, floor(visible body height / mean row height))` rows, measured from the DOM (fixed: row height; variable: mean of measured rows), minus the header; reveal; lands on a disabled row if that is where the count ends (Angular), then focus.
  - Space: toggle selection (A); Enter: starts editing the focused cell in wave 5; before wave 5 Enter on `_expander` / `_selection` cell activates its control and does nothing elsewhere. Escape: clear the range (wave 6); closes an open editor (wave 5); otherwise nothing.
  - Tab / Shift+Tab: NOT handled (D3): leave the grid through the roving model. Wave 5's editor re-adds Tab-advance while editing only, and must not apply when the commit was rejected (notes part 1 entry 4).
  - Ctrl+A is not claimed (wave 6 may select all cells).
- **Reveal:** after a focus move `virtual.reveal(row, key)` (virtual) or `cell.focus({ preventScroll: true })` then `scrollIntoView({ block: 'nearest', inline: 'nearest' })` with the `scroll-padding-*` of C.2 (non-virtual), so a focused cell never hides under the sticky header, footer or pinned columns. Reduced motion: `behavior: 'auto'` always.
- **Touch:** no new gesture in wave 4 except focus on tap (pointerdown with `pointerType=touch` focuses without opening a keyboard: cells are not editable until wave 5). Long-press range selection (`onLongPress` from `shared/touch.ts`, 500 ms / 10 px slop, passive listeners so scrolling is not blocked) is wave 6 and decided at touchstart (notes entry 19). Built-in controls keep their 44 x 44 coarse targets (wave 3 CSS). The roving cell ring must be visible in forced-colors mode (`outline` fallback; add a `@media (forced-colors: active)` rule).
- **Focus ring:** `data-focused` attribute (wave 3) is kept as the paint hook and mirrors `focused`; additionally `:focus-visible` shows the same ring, so a mouse click does not draw it twice. Setting `aria-current`? No: DOM focus is the AT signal now.
- **Events:** none new in wave 4 (Angular has none for focus). `focus-cell-change` is deliberately not added; a consumer reads `provider` via the element's `focusedCell` getter (`{rowIndex, columnKey} | null`) and calls `focusCell()`.
- **`QueryService` rule:** all lookups by drawn index go through `renderedRowAt` / `renderedTreeRowAt`; no controller re-derives row order.

### E.4 Aria-live (`AriaController`, `data-table-aria-controller.ts`, plan id `aria`)

Keep.
- **The debounce lesson (Angular `filterAnnounceTimer`, spec "announcement debounce 600 ms"):** an announcement driven by continuous input (typing, key repeat, a drag, a select-all that flips thousands of rows) is debounced, cancellable on disposal, and reads LIVE state when it fires. Announcements driven by a discrete user action (sort click, page change, column move) are immediate.
- Added in wave 4 (all via `host.announce`, text from the locale): page change (`Page {page} of {pages}`, immediate, from `page-change` / the `rows` topic when `pageIndex` changed); selection (`{count} rows selected` / `1 row selected` / `Selection cleared`, debounced 500 ms, count = selected ids that still exist in the data, so stale ids are not counted); group / tree expansion (none: the state is on the focused element; announcing it double-speaks); column move (immediate); column resize by keyboard (debounced 300 ms, last width wins: `{column} width {width} pixels`); busy / loading is `aria-busy` + the overlay `role=status` (wave 3), not announced twice. ## G. Risks and decisions

### G.1 Risks, ranked
1. **Variable-height virtual scroll feedback** (scroll anchoring double correction, ResizeObserver loop errors, jump on measurement, detail rows unmeasured). Three Angular reverts. Verified by C.4 cases 5 and 6 in real Chromium, with `overflow-anchor: none` asserted, frame-by-frame anchor-row position checks, and a console error listener that fails on "ResizeObserver loop".
2. **Roving tabindex under virtual scroll and re-render** (focus lost when a row is removed; ge-checkbox / custom-element controls re-enabling their own tabindex; viewport tab stop flip-flop). Verified by C.4 case 8, D.4 cases 1 and 7 (AX tree `focused`), a MutationObserver counting `tabindex="0"` over a scripted scroll.
3. **Merge conflicts in the hot files** (grid, element, query controller, columns controller). Mitigated by step 0 and the ownership table; verified by running the combined branch's full browser suite before each merge.
4. **Perf budgets unmet with custom-element cells** (construction cost per scroll step; keyed repeat destroys rows). Verified by C.4 case 9 and 10; fallback is positional recycling (D9).
5. **Sticky header / pinned columns hide the focused or scrolled-to cell** (native focus scroll ignores overlays). Verified by geometry assertions (cell rect inside the viewport minus header / footer / pinned rects) in D.4 case 2 and C.4 case 7.
6. **Pointer-gesture conflicts** (resize vs sort click, reorder vs click, touch drag vs scroll, pointer capture lost, click after drag). Verified by D/E tests with real CDP input, touch emulation, and the swallow-click tests.
7. **Rendered-index drift** (`data-row-index` vs `renderedRowAt`, `aria-rowindex` ordinal with group and detail rows). Verified by the invariant test in B.5 case 1 on every mode and by the AX tree row indexes.
8. **Hover/pointer leaks across test files** (known): `parkMouse()` and sized boxes; screenshots read on failure.
9. **Selection semantics divergences** (header scope across pages, cascade modes, stale ids): verified by node tests ported from the Angular specs listed in A.1, plus the browser check of scope.
10. **`contain: strict` with an unbounded host collapses to 0 height**: Diagnostics warning, demo CSS, docs.
11. **Locale / bundle budget**: new keys are en only; `size-budget.json` for `define.js` rechecked in the integration PR.
12. **Angular drift** (`509257d8` is past the notes): re-diff before closing.

### G.2 Angular oddities in this area we do not copy
- Tab as grid navigation (keyboard trap, D3). Focus never moving to a cell (D2). Arrow keys unflipped in RTL (D4). Enter / Space bound on non-focusable group rows (html 1261) and on cells over inner buttons (double activation family, notes entry 1; our toggle is a native `button`, no key binding on top of it).
- Per-cell listener sets (html 856-870, 7 copies): one delegated listener per event type.
- `columnWidths` written per pointermove (event storm); `parseInt` of widths in pin offsets and drag start (`10rem` -> 10); `innerHTML` cloning for autofit (loses shadow content, +24 fudge); body `cursor` / `userSelect` mutation; `document`-level mouse and touch listener pairs instead of pointer capture.
- `ensureFocusedCellVisible` = `scrollToRow` (jumps the focused row to the top on every key); `scrollToRow` unclamped; `getPageSize` ignores the sticky header and variable heights.
- Post-render DOM-walk ARIA stamping and `aria-colindex` omission when windowed (replaced by `computeGridAria` + absolute index, D7); `aria-expanded` on `role=row` in a plain `grid` (we use `treegrid` whenever grouping or tree is configured).
- Selection / expansion pruning absent (kept: intended); `expandedRows` default; AI fill not undoable (not wave 4).
- HTML5 DnD for columns (no touch, fake-rect specs): pointer based instead. Dev checks via `console.error` (we `console.warn` once).
- File-level: 6.4k-line component, effects-as-fields, `ComponentPoolService` (replaced by keyed `repeat`).
