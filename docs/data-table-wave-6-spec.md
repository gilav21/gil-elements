### J5 Lazy loading: spike result and mechanism
**Spike (D2 of wave 6): passed.** `pnpm run build` emitted `dist/data-table/lazy/{range,clipboard,row-drag,filter-panels,filter-builder}.js` (the five new entries) and `dist/chunks/data-table.js` contains `import("../data-table/lazy/range.js")` (and the other four): rollup rewrites the relative specifier to the entry file from whatever chunk the call lands in, and the file exists. The icons' `import('../icon/define.js')` (`data-table-icons.ts`) is emitted the same way. The published package resolves it: a relative import inside a package is not subject to its `exports` map, so the lazy files need no `exports` line. `scripts/size.mjs` counts what it should: its static-import regex does not match `import("...")`, so the lazy entries are NOT in `data-table/define.js` / `index.js` and each is measured and budgeted as its own entry (a stub is 20 to 140 B gzip); a shared chunk that a lazy entry and `define` both import counts in both, which is the conservative reading. Chosen mechanism for BOTH waves: **a build entry per lazy module, reached by a plain relative `import()` written in the code that needs it, behind `data-table-lazy.ts`.** Wave 5 lazy: the three panels (`lazy/filter-panels`), the builder (`lazy/filter-builder`), `ge-date-picker` (its own define entry). Wave 6 lazy: range and fill (`lazy/range`), paste (`lazy/clipboard`), row drag (`lazy/row-drag`); copy and flash stay eager. Wired already, so the mechanism is exercised end to end: `RangeSession`, `ClipboardController`, `RowDragController` call `lazyPart(...).sync(flag)` from `hostUpdate`, and `FilterUiController.prefetch()` calls `lazyElement(...).load()`; the loaded parts are empty classes. No addon fallback is needed.

2. **The range readout needs `enable-range-actions`, not only range selection** (cmp 2584: `rangeSelectionStats` is null without it, and for fewer than two cells). The fill handle needs only `enable-fill-handle` and a focused cell or a range (cmp 2753).
3. **Range mousedown calls `preventDefault`** (cmp 4320) and the viewport is `select-none`. That kills the native `dragstart` of a `draggable` row, so range selection + row drag only work together from the special columns (their cells return no address, `cellFromElement` 4306). We do not preventDefault the pointerdown (D12).
4. **The focus goes to the range ANCHOR, not the end** (`startRangeDrag` 4329): after a drag the focused cell is where the drag started; the keyboard extension moves the END. A 1x1 range collapses to plain focus on release (4364). `isCellSelected` = in the range, else the focused cell (cmp 5610): this is what the context-menu addon reads at a long press (cmp 1894, wave 7).
5. **Paste and fill do not emit `cell-edit`.** Only the commit path does (`applyValueSetter` 4797 pushes into the undo recording, `validateEdit` 4756 emits `edit-error` per rejected cell and also sets `cellEditError`). `writeCells` defaults match (`emitEdit` false, `report` true). Our paste and fill do NOT set the editor's error state (wave 5 owns it); consumers see `edit-error` per rejected cell and the totals in `cells-paste`.
6. **Row drag is not undoable and writes `data` in `onRowDrop`** (cmp 5915): one of the three places `data` is written (port doc 8). No `runAsCommand`. With `localReorder` off nothing moves.
7. **Angular's live drag preview** (`dragPreviewData`, cmp 5727, html 1344) re-orders the DOM under the pointer in the flat, non-virtual path only, while `getDropEdge` (6116) keeps indexing the pre-move list. We draw the indicator only, in every mode (D14, candidate bug AB6).
8. **Cell flash classes use Tailwind keyframes `flash-up|down|changed` that are not defined anywhere in the Angular repo** (the classes are asserted by spec 4577 and nothing else): colours, keyframes and reduced motion are ours to define (section D).
9. **No keyboard or touch alternative for row drag exists in Angular** (native DnD, html 996-1000). WCAG 2.2 SC 2.5.7 (dragging movements) and 2.1.1 ask for one: section C.5 adds Alt+Arrow and a public `moveRow`. The fill handle drag has the same gap: Ctrl+D (D3).
10. **Copy precedence** (cmp 4474): range, else focused cell, else selected rows; `copyCellRangeToClipboard` (4514) alone ignores `enableCopy`, the rest respect it. Rows come from `processedData()` which already is the DRAWN list (groups, tree, page), so rendered index and data index agree; ours reads `renderedRowAt(i)`.

### B.2 Lit design (package B: `ClipboardController`, id `clipboard`, eager copy + lazy paste `lazy/clipboard.ts`)
- **Copy is eager** (`enable-copy` defaults to true; the code is `toClipboardText` + a few scopes, under 1 KB gzip). `ClipboardService.copy(scope)` builds the grid from `QueryService` (never the DOM): cell text through `cellText(column, row)` (wave 3), rows through `renderedRows()`, `exportData()` for `all`, selected rows through `groupRows()` flattened when grouping is active (drawn order) else `sortedData()`, filtered by `rowSelection`; the formula guard is applied by `toClipboardText`. Range copy reads the rows from `renderedRowAt(i)`, so a range larger than the window (virtual) copies every row, not only the drawn ones; rows that do not exist are skipped.
- **Key handler `KEY_PRIORITY.clipboard` = 10:** Ctrl/Cmd+C when `enable-copy`, the target is not a text field (a copy inside an editor, a filter box or a detail-row input is the browser's), and something is copyable (range, else focused cell, else selected rows); Ctrl/Cmd+V when `enable-clipboard-paste`, not editing, a focused cell exists. The handler consumes (`preventDefault`) ONLY when the Async Clipboard method it needs exists; otherwise it returns false and the browser's native event takes over (next point). Results are announced through `host.announce` (`copiedAnnouncement*`, `pasteResultAnnouncement*`, `pasteRejectedAnnouncement`; discrete actions: immediate, not debounced).
- **Denied and missing paths (beyond Angular, D1):** `writeText` / `readText` rejections are caught: status `denied`, `copyFailedAnnouncement` / `pasteFailedAnnouncement`, nothing written, no event, NO unhandled rejection (AB1). `navigator.clipboard` missing (insecure context, old browser, Firefox `readText`): the controller registers delegated native `copy` and `paste` listeners on the viewport (target in a cell, not a text field, `!event.defaultPrevented`): `copy` sets `event.clipboardData.setData('text/plain', tsv)` and `preventDefault`; `paste` reads `event.clipboardData.getData('text/plain')` and calls `pasteText`. The same listeners serve the browser's own Paste / Copy menu entries. A permission prompt is the browser's; we never request permissions.
- **`pasteText(text, at)`** (pure planner `data-table-paste-apply.ts`, node-tested; the lazy chunk): `parseClipboardGrid(text)`, `restoreSpreadsheetText` per cell, `planPaste` from the focused cell (or `at`), values by `coercePasteValue(raw, currentValue)` (wave-1 rules: blank clears a number, text that is no number stays text, booleans follow `true`; deliberately NOT Angular's `Number('')` = 0, D9), ONE `runAsCommand(() => host.writeCells(requests))` so the paste is one undo step and one `data-change`; skipped: columns without `valueSetter`, rows not drawn; rejected: `editValidator` (an `edit-error` per cell, parity; they do not set the editor's error state); then `cells-paste` once with the Angular fields, the range set to the pasted rectangle (beyond Angular: the user sees what changed; D3b), announcement. Pasting while the table is `loading` or `readonly` (no setters) is a no-op `{ status: 'ignored' }`.
- **Public:** `copyCellToClipboard()`, `copyRowToClipboard(row)`, `copySelectedToClipboard()`, `copyCellRangeToClipboard()`, `copyAllToClipboard()` (all `Promise<void>` for parity, resolve even when denied), `ClipboardService.paste()` / `pasteText()` for consumers through `provider`.
- **Edge cases:** CRLF / CR / quoted multi-line cells (wave 1); a trailing newline; pasting a single cell over a range (Angular: only the focused cell; Excel fills the range: parity, documented); copying 100k rows (the string is built once, no per-cell DOM); copy of a custom-element cell (`cellText` is the column's text, not its rendered shadow content: the docs say a `cell` string is what is copied); grouped table copy order; tree; `stringifyValue` for dates; `navigator.clipboard.readText` hangs on a permission prompt (the handler is async and holds no state; a second Ctrl+V while one is pending is ignored); the focus moving during the await (the target cell is read at key time).

## C. Row drag reorder (package C: `RowDragController`, id `row-drag`, lazy chunk `lazy/row-drag.ts`)

### C.1 Angular behaviour
- Native HTML5 DnD on the row (`draggable` when `enableRowDrag` and the row is not disabled; html 996-1000, 1179-1183, 1388-1392), `dragstart` (cmp 5770: declines when off, disabled row or `loading`; `dataTransfer` id, `effectAllowed=move`; document `wheel` capture + `drag` listeners), `dragover` (5827), container `dragover` (5861: below the last row = drop after it), `drop` (5915), `dragend` (6094).
- Position (5786): flat = above / below by the half; tree mode = above / on / below by quarters (`on` = become a child, `parentId` on the event); a FLAT drag in a tree table is refused across depths and `on` becomes `below` (5799). Vetoes: disabled target row, `rowDragAllowDrop(dragRow, targetRow, position)`.
- Event (6037): `row-reorder { row, targetRow, position, previousId, nextId, parentId?, fromIndex, toIndex }` (indexes in the drawn list, neighbours of the final position); with `localReorder` (default) `data` is replaced by `reorderData` before the event (flat: next to `previousId`, else before `nextId`, else the end; tree: remove from its parent, insert above / below / inside through `setChildren`); an unknown row returns the input array.
- Auto-scroll near the top and bottom 40 px (5884, one rAF step per `dragover`); drop indicators: a 2 px primary line top / bottom, a primary frame for `on` (css already ported); the dragged row at 30 % opacity with a primary inset ring.
- Pinned by: spec 4655-5288 (flat, tree, flat-with-subrows depth rule), 5770-5946 (container drag over, auto-scroll), 6162-6222 (deep tree removal).

### C.2 Lit design
- **Pure core** (new `data-table-row-reorder.ts`, node-tested): `dropPosition(mode, relativeY)`, `depthCompatible`, `buildRowReorderEvent(state, rows, getRowId)` (the neighbour-id rules of cmp 6071-6088, tested at both ends and for `from < to` / `from > to`), `reorderFlat`, `reorderTree` (remove + insert with `getChildren` / `setChildren`, immutable), `siblingMove(row, direction, index)` for the keyboard (C.5). Ports spec 4817-4858, 5116-5197, 5218-5288, 6162-6222 one for one.
- **DOM:** the renderer (step 0) writes `draggable="true"` on a data row when `enable-row-drag`, the row is not disabled and the table is not `loading`; `?data-dragging` on the dragged row; the drop edge element `div[data-slot=data-table-drop-edge][data-edge=top|bottom|on][aria-hidden=true]` inside the target row. State (`draggedId`, `overIndex`, `overPosition`) lives in the controller and re-renders only when the target index or position changes (not on every `dragover`).
- **Events, delegated on the viewport (one listener per type, `ownEvents`):** `dragstart` (a `dragstart` that follows a TOUCH `pointerdown` is cancelled with `preventDefault`: touch row drag is unsupported as in Angular, and it must not fight the touch long-press range of wave 6 A, D12; a drag starting on a control or in a text field is cancelled too), `dragover` (position by the row rect; `preventDefault` + `dropEffect = 'move'` only for an accepted target; vetoes as Angular; the container area below the last row retargets to "after the last row"), `drop`, `dragend`, plus `Escape` (native DnD already ends with `dragend`). Cleanup on `dragend`, `drop`, `blur`, detach and when the flag turns off.
- **Auto-scroll:** `startAutoScroll({ edge: 40, maxSpeed })` from `shared/auto-scroll.ts` instead of Angular's one-step-per-`dragover` rAF and its `wheel` hijack: Angular installs a `passive: false` capture `wheel` listener on `document` for the whole drag (cmp 5780) that scrolls the table for EVERY wheel event of the page and is removed only in `clearRowDragState`; Chromium does not deliver wheel events during a native drag, and if `dragend` is lost the hijack stays (AB5). We add no wheel listener.
- **Virtual scroll:** the dragged row is kept drawn with `virtual.retain('row-drag', [index])` for the whole drag: a native `dragend` is not delivered when the source node is removed, and Angular's recycled source row loses it. Auto-scroll scrolls the viewport and the window follows; drop indexes are absolute drawn indexes (`data-row-index`), the target index is read from the row element.
- **Drop:** build the event from `renderedRows()` (the DRAWN list: grouped, tree, page, window all agree), `rowDragAllowDrop` checked again at drop, `localReorder` -> `model.set('data', reorderData(model.get('data'), event))` (one of the three `data` write places; one `data-change`; NOT `runAsCommand`: not undoable, parity D13), then `row-reorder` once, then `rowMovedAnnouncement`. A drop on the dragged row's own position emits nothing (`fromIndex === toIndex`); Angular's spec 4790-4816 and 4943 only pin the preview and the out-of-range cases, so pin this as a new case.
- **Sort, group and paging:** a drop reorders `data`, but a table sorted or grouped keeps drawing its own order (Angular too): the diagnostics warn once (step 0 stub), documented. With local paging `fromIndex` / `toIndex` and the neighbours are those of the PAGE (Angular), the reorder in `data` is by neighbour id so it lands correctly; pin with a node test.
- **Keyboard (beyond Angular, D4), `KEY_PRIORITY.rowMove` = 40:** with `enable-row-drag`, a focused cell on a non-disabled row, Alt+ArrowUp / Alt+ArrowDown moves the row one step among the DRAWN rows (flat) or among its siblings (tree, `siblingMove`), skipping disabled rows, honouring `rowDragAllowDrop`; it builds the same `RowReorderEvent` (`position` above / below the neighbour) and runs the same drop path (so `localReorder`, `row-reorder`, announcement); the DOM focus follows the moved row (the cell at the new index, `reveal` in virtual). Alt+Left / Right are the browser's history keys and are not used (indent / outdent of tree rows is out of scope; a consumer can drive `reorderData` with `position: 'on'`). The public `moveRow(row, 'up' | 'down')` is the single-pointer alternative for consumer buttons (SC 2.5.7). `rowDragHint` is stamped as `aria-description` on `[data-slot=table]` (one place, not 10k rows).
- **Edge cases:** drag a row onto itself (no event); drop on a disabled row (refused: no `preventDefault`, no indicator); `rowDragAllowDrop` throwing (treated as veto, logged once); tree drop `on` a descendant of the dragged node (a cycle: refused, Angular does not guard it, AB7); drag started inside a detail row; an editor open in another cell (wave 5: the row is not draggable while an editor is open in it, because a draggable ancestor breaks text selection inside an input in Firefox); RTL (the edge elements use `inset-inline`); `contain: strict` viewport + retained row z-order; two tables on a page (the `dataTransfer` payload is a private mime type `application/x-ge-data-table-row` plus the id, so a drop from another table or another page is ignored).

## D. Cell flash (package C, in `FormattingController`, eager)

- **Angular:** `setupCellFlashEffect` (cmp 1781): on every `data` / `columns` change diff all rows by id against a snapshot of every cell value (`diffCellValues` 1721, columns with `enableCellFlash === false` and `_`-keys skipped), `classifyChange` (1754: both `Number()` finite -> `up` / `down`, else `changed`), then a `setTimeout(duration)` clears the whole map; the classes use a fixed `0.5s` animation whatever the duration (1711-1718). Default `getRowId` warns and skips (cmp 1984).
- **Lit:** a pure `data-table-flash.ts` (`classifyChange`, `diffFlashes(prev, rows, columns, getRowId)`, node-tested; ports spec 4570-4655), driven from `FormattingController.hostUpdate()` when `enable-cell-flash` is on and `data` changed identity. Differences, all costs or clear bugs: the snapshot covers only the ROWS DRAWN (`renderedRows()` after each render, plus the window), so cost is O(drawn rows x flash columns) per data change, not O(all rows x all columns) (a 100k-row ticker would copy 100k maps every tick in Angular); a row that was not drawn before has no previous value and does not flash (Angular: same for a new id); expiry is PER CELL on one re-armed timer (Angular's first timer clears a later update's flashes early, cmp 1794-1797, AB4); the duration drives the css (`--ge-dt-flash-ms`, so `cell-flash-duration` and the animation agree); timers are `disposables`-owned and cleared on detach. `FormattingService.flash(rowId, key)` feeds `data-flash=up|down|changed` through `cellState`; classification keeps Angular's `Number()` rule (D15).
- **Look and reduced motion** (`data-table-drag.css`): tint `color-mix(in oklab, <colour> 20%, transparent)` with `--ge-dt-flash-up` (green), `--ge-dt-flash-down` (red), `--ge-dt-flash-changed` (yellow) defaults, and a keyframe that fades the tint out over the duration (`animation: ge-dt-flash var(--ge-dt-flash-ms, 500ms) ease-out`). Under `prefers-reduced-motion: reduce` there is no animation: the static tint stays for the duration (use `shared/motion.ts` `prefersReducedMotion()` only where JS needs it; the css rule is enough here). Colour must not be the only signal (port doc 6.4): the cell also gets a 2 px inline-start marker, solid for `up`, dashed for `down`, dotted for `changed`. No live announcement (a ticker would flood it).

## G. Size (data-table/define.js is about 77 KB gzip)

Measure first: step 0 includes a throwaway build that imports the wave-1 modules (`data-table-range.ts`, `data-table-fill.ts`, `shared/touch.ts` pieces) to show their real gzip cost, because today they are unreachable from `define.js` and tree-shaken. Rough estimate from the file's own density (about 8 bytes gzip per source line, 9.3k lines): the new ~1.2k lines plus the ~0.9k wave-1 lines that become reachable is **about +11 KB gzip (+14 %) if everything is eager**: A about 6, B about 2.5, C about 3 (row drag 2, flash 1), locale and css about 1.5 across them.
Recommendation (D2): **lazy, flag-gated `import()` for range + fill, paste and row drag; eager for copy and flash.** Reasoning: all of them default off (`enable-cell-range-selection`, `enable-range-actions`, `enable-fill-handle`, `enable-clipboard-paste`, `enable-row-drag`, `enable-cell-flash` are false), so a plain grid pays about 0; the exceptions are `enable-copy` (default true, but it is a short function over data the query already exposes, under 1 KB) and flash (small, and hooked into `FormattingController`, which is eager). The flag is known at the first update, so the chunk loads while the first render happens, not at the first gesture. The gate keeps working: the three lazy modules are build entries with their own budgets (A about 7 KB, B about 2.5 KB, C about 3 KB, rounded up with the usual 5 % headroom after measuring), while `define.js` grows by the shells, flash, locale keys and css only (about +3 to +4 KB, budget raised once in the integration PR). The alternative, opt-in addons (`import '@gilav21/elements/data-table/row-drag'`), saves the same bytes but makes `enable-row-drag` silently do nothing without the import, which breaks Angular parity of the attribute API; rejected unless the spike shows the dist `import()` of an entry is unreliable (then fall back to addons for row drag only and eager for the rest, +11 KB). Flash and copy never go lazy.

## H. Decisions (recommended defaults; Angular parity first)

- **D1. Clipboard path.** Parity: Ctrl/Cmd+C / V on keydown through `navigator.clipboard`, plus (beyond Angular) native `copy` / `paste` events through `clipboardData` when the API is missing, rejections caught with an announcement and no unhandled rejection. Default: yes.
- **D2. Lazy loading** of range + fill, paste and row drag behind their flags; copy and flash eager; lazy modules are budgeted build entries. Default: yes, subject to the dist spike.
- **D3. Beyond Angular for keyboard users:** Shift+Arrow range extension (the wave-4 marker promises it), Ctrl/Cmd+A (all drawn cells), Ctrl/Cmd+D (copy the first row down inside the range, the alternative to the fill-handle drag), all gated by the existing flags. **D3b:** paste selects the pasted rectangle. Default: yes.
- **D4. Row drag keyboard alternative:** Alt+ArrowUp / Down and public `moveRow` (SC 2.5.7). Tree indent / outdent not included. Default: yes.
- **D5. Anchor and focus:** focus stays on the range anchor, keyboard extension moves the end (Angular, Excel). Default: parity.
- **D6. Range after sort / filter:** clamp only (Angular `keepSelectionWithin`), the selection can point at other data after a sort. Alternative: clear the range on a `query` change. Default: parity, one-line switch if the owner wants it.
- **D7. Auto-scroll while a range or fill drag nears the viewport edge** (`shared/auto-scroll.ts`). Default: yes (Angular cannot select past one screen).
- **D8. Fill is downward only, one `runAsCommand` + one `writeCells`, no `cell-edit` events, `edit-error` per rejected cell, `fill-series` once.** Default: parity (the single write is the Angular bug fix AB3).
- **D9. Paste coercion:** wave-1 rules (a blank cell clears a number; `toAggregatableNumber`), not Angular's `Number('')` = 0. Stats count numbers the same way (not `Number(v)`: `null`, `''`, `true` are not numeric). Default: keep wave 1.
- **D10. Readout** only with `enable-range-actions` and 2+ cells, numeric aggregates only when `numericCount > 0`, the `Chart` button as a lazily defined `ge-button`. Default: parity.
- **D11. Fill handle** as one measured overlay (parity, existing css), not an in-cell child. Default: parity.
- **D12. Row `draggable` on the whole row** (parity), no handle; the pointerdown is NOT prevented (so range selection and row drag coexist on data cells); a `dragstart` after a touch pointer is cancelled (touch row drag unsupported, no clash with the long-press range). Default: yes.
- **D13. Row drop** writes `data` through the model (`localReorder`, one `data-change`) and is not undoable; `row-reorder` always fires. Default: parity.
- **D14. No live drag preview:** indicator only, in every mode (Angular previews in the flat non-virtual path only, with a stale indicator index, AB6). Default: yes.
- **D15. Flash:** snapshot of drawn rows only, per-cell expiry, duration also drives the css, reduced motion keeps a static tint, a non-colour marker; classification keeps Angular's `Number()` rule (so `null` -> 5 reads `up`, `true` -> `false` reads `down`). Default: yes.
- **D16. ARIA:** `aria-selected` on data cells and `aria-multiselectable` on the grid in range mode; readout is a named group, announced debounced, never a live region of its own. Default: yes.
- **D17. Touch long press** 500 ms / 10 px, passive until it fires, a long press on a selected cell left to the context menu (wave 7). Default: parity.
- **D18. Parallel work with wave 5:** one joint step-0 PR first, frozen shared files, session split, `KEY_PRIORITY` table, merge order 5 then 6 (F.3). Default: yes.

### Candidate Angular bugs (verified only by reading; nothing filed; verify against a running Angular build before filing)
- **AB1** cmp 4494, 4502 (-> 4256), 4482 (-> 4532) and 4439 (-> 2747): the copy and paste promises are neither awaited nor caught; with permission denied (or `readText` unsupported) the handler has already called `preventDefault`, nothing is copied or pasted, the user gets no feedback and an unhandled rejection is raised.
- **AB2** cmp 2696-2701: `coercePasteValue` uses `Number(raw)`, so an empty (or whitespace) pasted cell becomes `0` in a number column, and `'0x10'` / `'1e3'` coerce too.
- **AB3** cmp 2655-2661 (`fillColumn`) and 2708-2717 (`pasteCell`): each cell resolves its target row from `processedData()` AFTER the previous cell's `applyValueSetter` (4797, which also copies the whole `data` array per cell and calls `data.set` each time), so when the written column is the sort or filter key the rows move mid-write and later values land on the wrong rows; cost is O(cells x rows). Our `writeCells` already resolves first.
- **AB4** cmp 1781-1799: every data change that flashes arms a new `setTimeout` that clears the WHOLE flash map, so a second update cuts the first one's flash short; the animation is a fixed 0.5 s whatever `cellFlashDuration` says (1711-1718).
- **AB5** cmp 5780-5781 and 6102-6103: a `passive: false` capture `wheel` listener is added to `document` for the whole row drag and scrolls the table by every wheel event of the page; it is removed only by `drop` / `dragend`, and Chromium does not fire `dragend` when the source node was removed (a virtual-scroll row recycled out of the window), which leaves the page's wheel hijacked. Unverified.
- **AB6** cmp 5727-5747 with html 1344 and cmp 6116: the live preview re-orders the rows under the pointer while `getDropEdge` still indexes the pre-move list; the target under the pointer changes as rows move (indicator on the wrong row, possible oscillation). Flat, non-virtual path only.
- **AB7** cmp 5976-6035 (`reorderTreeData`): dropping a node `on` one of its own descendants removes it first and then does not find the target, so the node is silently lost from the tree (the `removed` node is dropped when `insertIntoTree` never matches `targetId`). Verify with spec 5147 data before relying on it.
- **AB8** cmp 4315-4320: the range `mousedown` `preventDefault` disables native row drag from data cells and prevents focus changes; `enableRowDrag` + `enableCellRangeSelection` only drag from special columns. (Not a defect per se: an undocumented interaction.)
- **AB9** (quirk) cmp 1754-1760: `classifyChange` through `Number()` counts `null`, `''`, booleans and `Date`s as numbers (`true` -> `false` is `down`, an empty cell -> 5 is `up`).
